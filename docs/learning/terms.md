# Terms

Tech terms defined while teaching, one line each. Domain language lives in `GLOSSARY.md`.

- **Modular monolith**: one deployable service whose code is split into internal modules that talk only through defined interfaces.
- **Distributed monolith**: separately deployed services that still must change and deploy together, paying microservice costs without the benefits.
- **Conway's law**: systems tend to mirror the communication structure of the org that builds them.
- **Origin**: scheme + host + port of a URL (`https://app.example.com:443`); the unit browsers use for security isolation.
- **Same-origin policy**: browser rule that blocks a page's JavaScript from reading responses from a different origin unless that server opts in.
- **CORS** (Cross-Origin Resource Sharing): the opt-in headers a server sends to let pages from other origins call it.
- **Path routing**: a gateway rule that picks the backend service by URL path, e.g. `/api/*` to one service and `/` to another.
- **Three-tier architecture**: presentation (web client), application (API), and data (database) layers, each deployed and scaled separately.
- **Platform component**: infrastructure the app depends on but the team configures rather than writes (gateway, database, cert-manager).
- **Schema migration**: a versioned, ordered script that changes the database schema (add table, add column) so every environment converges on the same shape.
- **Alembic**: the standard migration tool for SQLAlchemy (Python); each migration is a file with `upgrade()` and optional `downgrade()`.
- **Kubernetes Job**: a resource that runs a pod to completion once (exit 0 = success) instead of keeping it running like a Deployment.
- **Rolling update**: Kubernetes' default deploy, replacing old pods with new ones gradually, so old and new code run at the same time for a while.
- **Expand/contract** (parallel change): make schema changes in backward-compatible steps (expand, migrate code, then contract) so old and new code both work mid-rollout.
- **Shared database anti-pattern**: several services reading/writing the same tables, which couples them through the schema.
- **`.gitattributes`**: a committed file that tells Git how to treat paths (line endings, binary vs text, diff drivers) the same way on every machine.
- **`core.autocrlf`**: a per-machine Git setting that converts LF to CRLF on checkout; `.gitattributes` overrides it so the repo, not each laptop, decides.
- **UUIDv7**: a 128-bit ID whose leading bits are a timestamp, so it is unguessable yet sorts roughly by creation time (index-friendly, unlike random UUIDv4).
- **IDOR** (Insecure Direct Object Reference): a bug where changing an ID in a URL lets one user read or edit another user's row because ownership is not checked.
- **Single-table inheritance**: storing several related entity kinds in one table with a type column and nullable columns for each kind.
- **Polymorphic table**: one table holding rows of several kinds (e.g. all Catalog items with a `type` column); foreign keys can no longer guarantee they point at the right kind.
- **IANA timezone**: a named region with its full DST history, e.g. `America/Los_Angeles`; unlike a fixed offset like `-08:00`, it stays correct across daylight saving changes.
- **Generated column**: a column Postgres computes from other columns on write; only immutable expressions are allowed.
- **Soft delete**: marking a row deleted (`deleted_at`) instead of removing it; every query must then filter it out.
- **`ON DELETE CASCADE` / `RESTRICT`**: foreign key rules: deleting the parent deletes children automatically, or the database refuses while children exist.
- **CHECK constraint**: a boolean rule the database evaluates on every insert/update, rejecting rows that violate it.
- **Composite foreign key**: a foreign key over several columns, e.g. `(meal_id, meal_kind)` referencing `meals(id, kind)`, used to enforce cross-table rules.
- **Normalization**: structuring tables so each fact is stored once; duplication is only a problem when copies must stay in sync.
- **Denormalization**: deliberately storing a derivable fact a second time (e.g. a Sessions table) for speed or convenience, at the cost of keeping the copies in sync.
- **Materialized view**: a query result Postgres stores as a table and refreshes on demand; the read-speed step before hand-maintained denormalized tables.
- **Row-Level Security (RLS)**: Postgres policies that automatically filter which rows a session can read or write, e.g. only rows whose `user_id` matches the current user.
- **Immutable function**: a Postgres function guaranteed to return the same output for the same input forever; only these may feed generated columns and indexes.
- **Docker build context**: the directory sent to `docker build`; the Dockerfile cannot read files outside it.
- **Drift check**: a CI step that regenerates an artifact (e.g. `openapi.json`) and fails if it differs from the committed copy.
- **Helm**: the Kubernetes package manager; a chart is templated YAML plus a `values.yaml`, installed as a versioned release.
- **Kustomize**: built into `kubectl`; applies per-environment patches (overlays) to plain-YAML manifests (a base) without templating.
- **GitOps**: an in-cluster agent (e.g. Argo CD) continuously pulls the cluster to match what is committed in Git, instead of CI pushing changes in.
- **Rancher**: SUSE's platform for provisioning and managing many Kubernetes clusters from one UI.
- **Control plane**: the Kubernetes components that run the cluster (API server, scheduler, controller manager, etcd); workers run the app pods.
- **etcd quorum**: etcd needs a majority of members alive to accept writes; 3 members tolerate 1 failure, 1 member tolerates none.
- **Taint / toleration**: a taint on a node repels pods; only pods with a matching toleration may schedule there (kubeadm taints the control plane by default).
- **NAT NIC (VirtualBox)**: gives a VM outbound internet through the host; nothing can connect in. Vagrant requires it as NIC 1.
- **Host-only NIC (VirtualBox)**: a private network visible only to the host and its VMs (here `192.168.56.0/24`).
- **Bridged NIC (VirtualBox)**: puts the VM directly on the physical LAN as its own device, reachable from other machines such as a phone.
- **CIDR**: an IP range written as base/prefix length; `10.244.0.0/16` fixes the first 16 bits, giving 65,536 addresses.
- **Overcommit**: allocating more virtual resources than physically exist; safe for CPU (idle VMs yield it), risky for RAM (it cannot be reclaimed quickly).
- **Node eviction**: the kubelet killing pods when a node runs low on memory or disk, to protect the node itself.
- **L2 announcement**: a node answering ARP requests for a LoadBalancer IP so other LAN devices send traffic for that IP to it (Cilium's MetalLB-style feature).
- **Provisioning**: turning a blank machine into a configured one (packages, settings, services).
- **Ansible control node**: the machine that runs `ansible-playbook` and connects over SSH to the managed hosts (here, the dev VM).
- **Ansible inventory**: the file listing managed hosts, their groups (e.g. `workers`), and how to reach them.
- **Ansible role**: a reusable bundle of tasks, templates and defaults for one concern (e.g. `containerd`), composed by a playbook.
- **Idempotent**: running an operation twice leaves the system the same as running it once; for Ansible, the second run reports `changed=0`.
- **cloud-init**: the standard first-boot hook on cloud VMs that injects SSH keys and runs a short bootstrap script.
- **kubeadm join token**: a short-lived bearer token a new node presents to the control plane to join the cluster.
- **`StrictHostKeyChecking=accept-new`**: SSH trusts a host's key the first time it is seen and refuses if that key later changes.
- **`apt-mark hold`**: pins an installed Debian/Ubuntu package so automatic or manual upgrades skip it; `dpkg_selections` is the Ansible way to set it.
- **Kubespray**: the Kubernetes SIGs Ansible project that installs production kubeadm clusters; highly configurable.
- **Molecule**: a framework for testing Ansible roles in throwaway containers or VMs.
- **StatefulSet**: a Kubernetes workload whose pods keep a stable name and their own volume across restarts.
- **Operator**: an in-cluster controller that runs one piece of software for you (failover, backups, upgrades) from a declared desired state.
- **CRD** (Custom Resource Definition): a new object type added to the Kubernetes API, e.g. CNPG's `Cluster`, that an operator watches.
- **CloudNativePG (CNPG)**: the CNCF Postgres operator; handles replication, failover, backups to object storage and point-in-time restore.
- **Streaming replica**: a read-only Postgres copy that replays the primary's WAL as it is written.
- **Failover**: promoting a replica to primary when the primary is lost.
- **WAL** (write-ahead log): the journal Postgres writes before changing data files; used for crash recovery, replication and point-in-time restore.
- **Pod anti-affinity**: a scheduling rule that keeps matching pods off the same node; "required" makes it a hard rule.
- **Shared-nothing replication**: each database instance keeps its own local disk and the database itself copies data between them, instead of sharing network storage.
- **CPU limit throttling**: a container with a CPU limit is paused when it hits the limit, even if the node has idle CPU.
- **`shared_buffers`**: Postgres' in-memory cache of table and index pages.
- **PgBouncer**: a lightweight proxy that multiplexes many client connections onto a few Postgres connections.
- **Barman Cloud**: the tool CNPG uses to ship base backups and WAL to S3-compatible object storage.
- **Aggregate**: a cluster of objects always read and written together as one unit through its root (a Meal and its Food Entries), so its rules are checked in one place.
- **Debounce**: wait until input pauses (e.g. 150 ms after the last keystroke) before acting, so fast typing sends one request instead of many.
- **Typeahead**: suggestions that update as the user types.
- **Trigram**: a 3-character chunk of text; `pg_trgm` ranks strings by how many trigrams they share, which tolerates typos.
- **Subsequence matching**: fzf-style fuzzy match where the query's letters appear in order but not adjacent ("chkbrst" finds "chicken breast").
- **Inverted index**: a search-engine structure mapping each term to the documents containing it; the core of Lucene and OpenSearch.
- **Dual write**: writing the same change to two systems (e.g. Postgres and a search engine) and keeping them in sync; breaks when one write succeeds and the other fails.
- **Keyset (cursor) pagination**: fetch the next page as "rows after this sort key" instead of "skip N rows"; stable under inserts and fast at any depth.
- **RFC 9457 Problem Details**: a standard JSON error body (`type`, `title`, `status`, `detail`) served as `application/problem+json`.
- **"/me" pattern**: the API infers the caller from their credentials instead of taking a user ID in the URL.
- **Optimistic concurrency**: a write carries the version it read (`If-Match: <ETag>`); the server refuses with `412` if someone changed it since.
- **ETag**: a response header holding an opaque version tag of a resource.
- **Liveness probe**: a Kubernetes check that the process is alive; failing it restarts the container.
- **Readiness probe**: a Kubernetes check that the pod can serve traffic; failing it removes the pod from Service endpoints without restarting it.
- **`operationId`**: the unique, stable name of one endpoint in an OpenAPI schema; code generators and MCP wrappers use it as the function or tool name.
- **Additive change**: an API change old clients safely ignore (new optional field, new endpoint); removing or renaming something is breaking.
- **SPA (single-page app)**: the browser loads one HTML page and a JS bundle once; JS draws every screen and fetches data as JSON.
- **TypeScript**: JavaScript plus type annotations checked at build time, then stripped to plain JS.
- **React**: a UI library where components describe what the screen should look like for the current state, and React updates the DOM to match.
- **Vite**: a front-end build tool: a fast dev server, plus a production bundler that emits static files.
- **`openapi-typescript` / `openapi-fetch`**: the first turns `openapi.json` into a TypeScript types file; the second is a tiny `fetch` wrapper that type-checks every call against it.
- **Multi-stage Dockerfile**: one stage builds (with compilers, Node), a later stage copies only the output, so build tools never ship in the final image.
- **Content-hashed assets**: build output named by a hash of its contents (`app.3f9a1c.js`), so it can be cached forever; a change gets a new name.
- **SPA fallback**: the web server answers any unknown path with `index.html` so client-side routes survive a refresh or a bookmark.
- **Client-side routing**: the JS app maps URLs to screens and changes the URL without a page load (React Router).
- **TanStack Query**: a library that fetches, caches, retries and refetches server data, so components don't hand-manage loading and error state.
- **PWA (progressive web app)**: a website that can be installed to the home screen and, with a service worker, work offline.
- **Web app manifest**: a JSON file giving a site its home-screen name, icon and full-screen launch.
- **Service worker**: a background script the browser runs for a site; it can intercept requests to serve offline or queue writes.
- **ESLint / Prettier**: a linter that flags bug-prone code, and a formatter that rewrites code to one style so diffs show only real changes.
- **Headless UI library**: components that supply behaviour, keyboard handling and screen-reader roles but no styling (React Aria).
- **React Aria Components**: Adobe's headless React library for accessible widgets (combobox, dialog, listbox); exposes state as `data-*` attributes to style against.
- **Utility-first CSS (Tailwind)**: styling with many small single-purpose classes in the markup (`rounded-xl px-3`) instead of a separate stylesheet per component.
- **Combobox**: a text input joined to a suggestion list, with a defined keyboard and screen-reader pattern (WAI-ARIA).
- **Bottom sheet**: a panel that slides up from the bottom of a phone screen over the current page; the mobile form of a dialog.
- **Secure context**: a page served over HTTPS or from `localhost`; browsers expose some APIs (`crypto.randomUUID`, clipboard, service workers) only there.
- **HMR (hot module replacement)**: the dev server swaps a changed module into the running page without a full reload; it relies on a file watcher noticing every save.
- **Out-of-order responses**: a slower, older request answering after a newer one; a search box must discard it or show stale results.
- **tmux**: a terminal multiplexer: split panes and windows inside one terminal, in sessions that keep running after you disconnect.
- **VS Code Remote-SSH**: an extension that runs VS Code's backend on a remote machine over SSH, so the editor on Windows edits files on the VM.
- **SSHFS**: mounts a remote machine's folder over SSH so it looks like a local drive; convenient but slower and weaker at file watching.
- **`connection: local` (Ansible)**: Ansible runs tasks directly on the machine it is invoked on instead of over SSH.
- **uv / `uv.lock`**: Astral's fast Python package and version manager; installs Python itself from a `.python-version` file, and the lockfile records the exact version and hash of every dependency.
- **SSH agent forwarding**: a remote machine borrows the keys in your local SSH agent for the life of the connection, so no key is stored remotely.
- **GNU Stow**: a symlink manager; each package folder mirrors `$HOME`, and `stow <pkg>` links every file to the same path under `$HOME`.
- **Runbook**: a written step-by-step procedure for an operational task, for whoever runs it next (often you, months later).
- **Gateway API**: the Kubernetes standard for routing outside traffic into the cluster: a `Gateway` (listener on a port/IP) plus `HTTPRoute`s (path/header rules to Services); Cilium implements it with Envoy.
- **Sidecar**: a second container in the same Pod as the app, sharing its network (`localhost`); used to add a concern (auth, proxying, logging) without changing the app.
- **Bearer token**: a secret sent as `Authorization: Bearer <token>`; whoever holds the token is let in.
- **HTTP Basic Auth**: browser-native username/password prompt sent as a base64 header; unreliable in iOS home-screen apps.
- **ext_authz**: an Envoy filter that asks an external service to allow or deny each request before it is forwarded.
- **WireGuard (Cilium transparent encryption)**: encrypts pod-to-pod traffic between nodes with a kernel VPN, enabled by one Cilium setting; no certificates or app changes.
- **mTLS**: both sides of a connection present certificates, so each proves its identity as well as encrypting traffic.
- **`BackendTLSPolicy`**: Gateway API object that makes the Gateway use TLS to the backend Service, verifying its certificate.
- **HSTS**: a response header telling a browser to use only HTTPS for a host for a set time; a broken certificate then cannot be clicked through.
- **DNS rebinding protection**: a router feature that drops DNS answers pointing at private IPs; can break "public name, LAN address" setups.
- **DNS-01 challenge**: Let's Encrypt proves you own a domain by checking a TXT record in its DNS, so no public server is needed.
- **`RequestRedirect` (Gateway API)**: an `HTTPRoute` filter that answers with a redirect, used for HTTP to HTTPS.
- **WAL (write-ahead log)**: Postgres writes every change to a sequential log before the data files; shipping this log elsewhere is how you copy the database continuously.
- **Base backup**: a full copy of the database files at one moment; restorable only together with the WAL written after it.
- **PITR (point-in-time recovery)**: restoring a base backup and replaying WAL up to a chosen timestamp, e.g. just before a mistake.
- **WAL archiving**: continuously copying finished WAL segments to backup storage (roughly every minute under light load).
- **Object storage**: stores whole files ("objects") under a key in a flat bucket, read and written over HTTP; no directories, no editing in place.
- **Bucket**: a named container of objects; access keys are granted per bucket.
- **Garage**: software that serves an S3-compatible object storage API from a plain disk; here the backup target on the dev VM.
- **MinIO**: the object store first chosen here; its open-source edition was archived, so Garage replaced it (ADR 0011).
- **Garage layout**: the record of which nodes store data and their share of it; nothing works until one is applied.
- **systemd unit**: a small file telling Linux's service manager how to run a program, restart it and start it at boot.
- **fsync**: forces written data from memory onto the disk, so a power cut cannot lose it; slower, but safe.
- **`no_log`**: tells Ansible not to print a task's values, so secrets stay out of its output.
- **S3-compatible**: speaks Amazon S3's HTTP API, so tools written for S3 work against Garage, B2, R2 or AWS by changing endpoint and credentials.
- **Barman Cloud plugin**: CNPG's plugin that sends base backups and WAL to S3-compatible storage and restores from it.
- **`serverName` (CNPG)**: the folder name a cluster uses in the backup bucket; a recovered cluster needs a new one, since two histories cannot share a folder.
- **Recovery bootstrap (CNPG)**: creating a new `Cluster` from a backup instead of an empty database; only possible at creation, never in place.
- **Retention policy**: how long backups are kept before the operator deletes them (7 days here).
- **Restore drill**: deliberately restoring from backup to prove it works before you need it.
- **btree index**: Postgres's default index, a sorted tree; serves equality, ranges and `ORDER BY` when the column order matches the query, and can be read backwards.
- **Composite index and column order**: one index over several columns, usable only left to right; `(user_id, day, occurred_at)` serves `user_id`, then `user_id + day`, but not `day` alone.
- **Index-only scan / `INCLUDE`**: extra columns stored in the index leaf so a query can be answered without touching the table.
- **Foreign keys are not auto-indexed (Postgres)**: the child column needs its own index, or joins and cascading deletes scan the whole table.
- **`EXPLAIN (ANALYZE, BUFFERS)`**: runs the query and prints the chosen plan with real timings and page reads; the evidence that an index is used.
- **Trigram (`pg_trgm`)**: a 3-letter chunk of a string; strings sharing many trigrams are similar, which gives typo-tolerant matching.
- **GIN vs GiST**: two index types for composite values like trigrams; GIN looks up faster, GiST is larger but can return nearest matches in order.
- **`similarity` vs `word_similarity`**: whole-string vs "does the query match part of the name" scoring; typeahead needs the second, duplicate checks the first.
- **`SET LOCAL`**: changes a Postgres setting for the current transaction only, used for per-query trigram thresholds.
- **Seed data**: deterministic synthetic rows loaded to make query plans realistic when real data is too small.
- **URL state**: keeping a view's parameters (such as the viewed Day) in the address (`?day=...`) rather than in memory, so reload, back button and links from other screens land in the same place.
- **Deep link**: a URL that opens the app directly at a specific screen and state, e.g. a Day.
- **Disclosure row (accordion)**: a collapsed summary row that expands in place on tap to show its detail, keeping long lists short.
- **Native date picker**: `<input type="date">`, which the phone renders as its own OS date chooser, so we write no calendar widget.
- **Integration test**: exercises several real parts together (here HTTP handler, SQL and a real Postgres) instead of mocking the neighbors.
- **Unit test**: tests one pure function in isolation; cheap, but blind to how pieces connect.
- **Testcontainers**: a library that starts a throwaway Docker container (here Postgres 18) from inside the test run and removes it afterward.
- **Test transaction rollback**: each test runs inside a database transaction that is rolled back at the end, so tests stay isolated without re-creating the schema.
- **MSW (Mock Service Worker)**: intercepts network calls in tests and returns canned responses, so UI tests need no real server.
- **Schemathesis**: reads an OpenAPI file and generates many requests to check every endpoint matches its schema and never crashes.
- **Smoke test**: a tiny post-deploy check that the core path works on the real system.
- **kubeconform**: validates Kubernetes manifests against the official schemas without needing a cluster.
- **Required status check / `ci-gate`**: branch protection blocks merges until named checks pass; one always-running gate job avoids path-filtered checks hanging as pending.
- **Flaky test**: a test that sometimes fails with no code change; erodes trust in CI, so it is fixed or removed.
- **Threat model**: a short list of who or what you defend against and what you deliberately do not; it decides how much security machinery is justified.
- **`kubectl create --dry-run=client -o yaml | kubectl apply -f -`**: renders an object locally and applies it, turning an imperative `create` into a re-runnable step that reports `unchanged`.
- **argv**: a process's command-line arguments; any user on the machine can read them with `ps`, so secrets never go there.
- **`kubernetes.io/basic-auth`**: a Secret type the API server checks for a `username` or `password` key; CNPG requires it for role passwords.
- **Kubernetes Secret**: a cluster object holding sensitive values for pods to read as env vars or files; base64-encoded, which is an encoding, not encryption.
- **etcd encryption at rest**: an API server setting that encrypts Secrets inside etcd; off by default, and skipped here because reaching etcd already takes host access.
- **Least privilege**: give each component only the access it needs, so a bug or breach in it can do limited damage.
- **DDL vs DML**: SQL that changes the schema (`CREATE`, `DROP`) vs SQL that changes rows (`INSERT`, `UPDATE`, `DELETE`).
- **`ALTER DEFAULT PRIVILEGES`**: tells Postgres which grants to apply automatically to tables a given role creates later.
- **SOPS + age**: SOPS encrypts values inside YAML files so they can be committed; age is the small encryption tool that holds the key.
- **SealedSecrets**: a cluster controller that decrypts secrets committed to git, using a private key held in that cluster.
- **External Secrets Operator**: a controller that copies values from an outside store (AWS, Azure, Vault) into Kubernetes Secrets.
- **Secret rotation**: replacing a secret with a new value so the old one stops working.
- **`CreateContainerConfigError`**: a pod state meaning a Secret or ConfigMap it needs is missing; Kubernetes keeps retrying, so it recovers once the object exists.
- **`managed.roles` (CNPG)**: Postgres roles declared on the `Cluster` itself, which the operator creates and regularly compares with the database.
- **`DatabaseRole` (CNPG)**: a separate resource for one role, applied only when it or its Secret changes.
- **`cnpg.io/reload` label**: marks a Secret so CNPG applies changes to it immediately rather than at a later reconciliation.
- **Guardrail vs boundary**: a guardrail stops accidents but can be stepped around; a boundary is enforced, such as by a separate user account.
- **Push vs pull deploy**: push means an outside system runs `kubectl apply` against the cluster; pull means an agent inside the cluster fetches changes, so no outside system needs cluster credentials.
- **Argo CD**: the GitOps agent that watches a git path and applies it to the cluster.
- **Argo CD `Application`**: one Argo resource saying "keep this git path synced to this namespace".
- **Auto-sync / self-heal**: Argo applies new commits by itself / reverts manual changes made in the cluster.
- **Sync hooks (`PreSync`, `PostSync`)**: Jobs Argo runs before or after applying the app; the sync waits for them and stops if they fail.
- **`hook-delete-policy: BeforeHookCreation`**: Argo deletes the previous hook Job before creating a new one, so a fixed Job name works every sync.
- **Expand-then-contract migration**: add new schema first and remove old schema in a later deploy, so old and new code both work during a rollout.
- **GHCR**: GitHub Container Registry, which stores container images next to the repo.
- **Image tag vs digest**: a tag is a movable label (`:abc123`); a digest is the immutable content hash.
- **Immutable SHA tag**: tagging an image with its git commit SHA so a tag always means the same build.
- **Branch ruleset / bypass actor**: GitHub rules protecting a branch; a bypass actor is allowed past them (here, deploy keys, ADR 0018).
- **Deploy key**: an SSH key that grants access to a single repo, read-only unless you say otherwise.
- **Drift (GitOps)**: the cluster no longer matches git.
- **Rollback by revert**: undoing a deploy by reverting the git commit, so the same pipeline redeploys the old version.
- **`docker buildx` layer cache**: reuses unchanged image layers between builds to speed up CI.
- **GitHub Actions**: GitHub's built-in automation; a workflow file in `.github/workflows/` runs jobs on GitHub-hosted machines when events like a PR happen.
- **Workflow / job / step**: a workflow is one YAML file; it holds jobs (each on its own fresh runner, in parallel unless chained with `needs`); a job holds steps run in order.
- **Runner**: the machine that executes a job (`ubuntu-24.04` is a GitHub-hosted Linux VM, thrown away afterward).
- **Path filter**: a check of which files a PR changed, used to skip jobs that have nothing to do (here via `dorny/paths-filter`).
- **Status check / required check**: a pass/fail result shown on a PR; a required one blocks merge until it passes.
- **`ci-gate`**: our single required check; it always runs and fails only if a job it waits for failed, so skipped jobs never leave the PR stuck "pending".
- **`needs` / `if: always()`**: `needs` makes a job wait for others; by default it is skipped if one of them failed or was skipped, so `always()` forces the gate to run and judge the results itself.
- **Concurrency group**: a label so a newer run of the same workflow cancels the older one.
- **`GITHUB_TOKEN`**: a short-lived credential GitHub creates for each workflow run; its `permissions:` block sets what it can do, and pushes made with it do not start new workflow runs.
- **`paths-ignore`**: a workflow trigger filter; a push that touches only the listed paths starts no run.
- **Bot commit**: a commit made by automation rather than a person; here, CI writing image tags to `main` with a deploy key.
- **GitHub App**: an identity you register with GitHub that gets short-lived tokens from a private key; the usual way to give automation its own login at a company.
- **Pinning an action to a commit**: `uses: owner/action@<full sha>` instead of a tag, because a tag can be moved to different code and a commit cannot.
- **Branch ruleset**: GitHub rules on a branch (require a check, block force-push); on free plans they need a public repo.
- **gitleaks**: a scanner that searches files and git history for strings shaped like secrets (API keys, tokens, private keys).
- **Redaction (`--redact`)**: hiding the matched secret in scan output so the CI log does not leak it a second time.
- **yamllint**: a linter for YAML syntax and style.
- **`.editorconfig`**: a file editors read so every contributor gets the same indentation, line endings and final newline.
- **`.gitignore`**: patterns for files git must never track (secrets, caches, editor state).
- **`fetch-depth: 0` / `--log-opts`**: `fetch-depth: 0` makes the checkout download all history and branches; `--log-opts` tells gitleaks which commit range (a `git log` argument) to scan, so a PR is judged only on its own commits.
- **Vagrant**: a CLI that creates and destroys VMs from a committed text file, so a machine can be rebuilt instead of hand-maintained.
- **Vagrantfile**: the Ruby file describing one or more VMs (image, CPU, RAM, network); Vagrant commands act on the one in the current folder.
- **Vagrant box**: the prebuilt VM image a machine starts from; pinning `box_version` keeps rebuilds on one published release, though only a checksum would prove the bytes match.
- **Vagrant provisioner**: a step Vagrant runs inside the VM after boot (upload a file, run a script); by default only on the first `vagrant up`.
- **Synced folder**: a host folder mounted inside the VM; turned off here so the VM depends on nothing from the host.
- **`.vagrant/`**: Vagrant's per-folder state, linking the folder to its VM and holding that VM's generated SSH private key; never committed.
- **SSH key pair**: a private key that stays secret and a public key placed on servers; a server admits you by checking you hold the private half.
- **ed25519**: the modern, short, fast SSH key type, and the default choice for new keys.
- **Host key / `known_hosts`**: a server's own identity key, and the file where your SSH client remembers it, so an impostor at the same IP gets noticed.
- **`StrictHostKeyChecking accept-new`**: trust a host's key the first time, refuse if it later changes; a rebuilt VM has a new key, so clear the old entry with `ssh-keygen -R`.
- **Git worktree**: a second folder attached to the same repo with its own branch checked out, so two pieces of work do not disturb each other.
- **Ansible playbook**: a YAML file mapping hosts to the roles and tasks to run on them; `dev.yml` is one.
- **Ansible task / module**: a task is one step; it calls a module (`apt`, `file`, `git`) that checks current state and changes only what differs.
- **Ansible handler / `flush_handlers`**: a task that runs only when another task notifies it, normally at the end of the play; `flush_handlers` runs pending ones immediately.
- **`changed_when` / `creates`**: `command` cannot know if it changed anything, so `changed_when` decides from its output and `creates` skips it if a file exists; both keep `changed=0` honest.
- **`become`**: run an Ansible task as root through sudo; everything else runs as the login user.
- **ansible-lint profile**: a named strictness level; `production` is the strictest.
- **deb822 source**: the modern apt repo file format (`/etc/apt/sources.list.d/*.sources`), one block of `URIs`, `Suites`, `Components`, `Signed-By`.
- **apt signing key**: the publisher key tied to a repo; apt refuses packages it did not sign.
- **apt version pin (`pkg=version`)**: installs that exact package version, so a rebuild does not silently pick up a newer one.
- **`docker` group**: members can use the Docker socket without sudo, which is effectively root on the machine; group changes apply at the next login.
- **Checksum pin**: a committed sha256 of a download, so a changed or tampered file fails the install.
- **Terraform**: a tool that creates cloud resources (VMs, networks) from committed text files; it replaces Vagrant here when the project moves to a cloud.
- **Multi-machine Vagrantfile**: one file defining several VMs with `config.vm.define`; settings outside the `define` block apply to all of them.
- **`private_network` / `public_network`**: Vagrant's names for a VirtualBox host-only NIC and a bridged NIC.
- **Default route**: where a machine sends traffic for any address it has no more specific route to; normally there should be exactly one.
- **Route metric**: the priority of a route, lower wins; two default routes with equal metrics leave the choice to the order they were added.
- **FastAPI**: a Python web framework that builds routes, validation and the OpenAPI schema from type hints.
- **Pydantic**: a library that validates data against typed Python classes; FastAPI uses it for request and response bodies.
- **Dependency injection (`Depends`)**: a route declares what it needs and FastAPI supplies it, so tests can swap in a replacement through `dependency_overrides`.
- **SQLAlchemy engine / session**: the engine owns the connection pool; a session is one unit of work on a connection.
- **psycopg**: the driver that speaks the Postgres protocol for Python; SQLAlchemy sits on top of it.
- **Savepoint**: a marker inside a transaction that can be rolled back to; it lets code "commit" inside a test whose outer transaction is later undone.
- **Structured logging**: each log line is a JSON object, so tools can filter by field instead of parsing text.
- **`ruff`**: a fast Python linter and formatter.
- **`pyright`**: a static type checker; strict mode rejects anything whose type it cannot determine.
- **ASGI**: the standard interface between a Python async web server and a web app.
- **Uvicorn**: the ASGI server that listens on the port and hands each request to FastAPI.
- **Lifespan**: FastAPI's startup and shutdown hook, used here to create and close the connection pool.
- **TCP keepalive / `tcp_user_timeout`**: keepalives probe an idle connection; `tcp_user_timeout` caps how long sent data may go unacknowledged; both detect a peer that vanished without closing.
- **`ansible.cfg`**: Ansible's settings file, read from the directory you run in; here it names the inventory and SSH options.
- **Ansible collection**: a versioned package of modules from Ansible Galaxy, pinned in `requirements.yml`; `community.general.modprobe` comes from one.
- **`reset_connection`**: closes Ansible's open SSH connection to a host, so the next task connects fresh.
- **`throttle`**: limits how many hosts run a task at once; 1 protects a shared file from parallel writes.
- **Swap**: disk used as overflow RAM; off on nodes by default, because the kubelet's memory accounting assumes memory is real RAM.
- **Kernel module**: code loaded into the running Linux kernel on demand; `modules-load.d` loads it again at boot.
- **sysctl**: a kernel setting changed at run time; files in `/etc/sysctl.d/` reapply it at boot.
- **`overlay`**: the filesystem that stacks image layers into one view, which is how containers share read-only layers.
- **`br_netfilter`**: kernel module that sends traffic crossing a Linux bridge through iptables, so Kubernetes network rules see it.
- **IP forwarding**: lets a machine pass packets between interfaces like a router; off by default, required so pod traffic can cross a node.
- **cgroup**: a kernel feature that limits and measures a group of processes' CPU and memory; v2 is the single unified tree.
- **cgroup driver**: what manages cgroups for containers; containerd and the kubelet must both use `systemd`, the manager that already owns the tree.
- **containerd**: the daemon that pulls images and runs containers; Docker is built on it, but Kubernetes talks to it directly and needs nothing from Docker.
- **CRI (Container Runtime Interface)**: the API the kubelet uses to talk to a runtime such as containerd.
- **runc**: the small program containerd calls to actually start a container process.
- **Netplan**: Ubuntu's network config layer; YAML in `/etc/netplan/`, merged in name order, rendered for systemd-networkd.
- **Router advertisement (RA)**: how an IPv6 router announces itself; hosts that accept it gain an address and a default route, with no DHCP involved.
- **SSH drop-in**: a file in `/etc/ssh/sshd_config.d/`; for most settings sshd keeps the first value it reads, so name order decides who wins.
- **kubeadm preflight**: kubeadm's own checks that a machine is ready to join a cluster; `kubeadm init phase preflight --dry-run` runs them alone.
- **`package-lock.json` / `npm ci`**: the lockfile records the exact version of every direct and indirect dependency; `npm ci` installs precisely that and fails if it disagrees with `package.json`.
- **`engines`**: the `package.json` field naming the Node versions a project supports; `engine-strict` in `.npmrc` turns a mismatch into a failed install.
- **Content hash**: a fingerprint of a file's bytes put in its name (`index-CZaudM2M.js`), so new content means a new URL and old URLs can be cached forever.
- **`Cache-Control: no-cache`**: the browser may store the file but must ask the server if it changed before using it; despite the name, this is not `no-store`.
- **`try_files`**: nginx tries each path in order and serves the first that exists; the last entry is the fallback, a URI or a status such as `=404`.
- **`tsc --noEmit`**: runs the TypeScript compiler as a checker only; Vite strips types without checking them, so this is the only step that catches type errors.
- **jsdom**: a simulated browser DOM in Node, so component tests run without a real browser.
- **Vitest / React Testing Library**: Vite's test runner, and helpers that find elements the way a user does (by role and name), not by internals.
- **`DataView`**: reads and writes numbers at byte offsets in a buffer, big-endian by default; used to lay out the UUIDv7 bytes.
- **`npm audit`**: checks installed packages against known advisories; `--omit=dev` limits it to what ships to users.
- **`kubeadm init` / `join`**: `init` creates the control plane (certificates, API server, etcd) on one node; `join` connects another node's kubelet to it.
- **kubeconfig**: a file holding a cluster's address and a credential; `kubectl` and Helm read `~/.kube/config`. The admin one is full control of the cluster.
- **CNI (Container Network Interface)**: the plugin standard that gives pods their IPs and connectivity; nodes stay NotReady until one is installed. Cilium is ours.
- **kube-proxy**: the default per-node program that implements Services, usually with iptables rules.
- **eBPF**: small verified programs loaded into the running Linux kernel, here to route and load-balance packets without a userspace hop.
- **kube-proxy replacement**: Cilium implementing Services in eBPF, so kube-proxy is not installed.
- **IPAM (IP Address Management)**: how pods get IPs. `ipam.mode: kubernetes` uses the per-node `podCIDR` slices cut from kubeadm's `podSubnet`.
- **ARP**: how a device on a LAN asks "who has this IP?" and learns the MAC address to send to.
- **Gratuitous ARP**: an unprompted ARP announcement that tells neighbours an IP has moved to a new MAC.
- **Lease (Kubernetes)**: a small API object used for leader election; the node holding a Service's lease answers ARP for its IP.
- **Server-side apply**: `kubectl apply --server-side`: the API server merges the change and tracks field ownership, with no size-limited annotation on the object.
- **Expression index**: an index on a computed value such as `lower(name)`; a query uses it only when it repeats the same expression.
- **Covering index**: an index that also stores extra columns (`INCLUDE (meal_id)`), so a query can be answered without visiting the table.
- **Trusted extension**: a Postgres extension that a non-superuser with `CREATE` on the database may install; `pg_trgm` is one.
- **SQLSTATE**: the five-character code Postgres returns with every error; stable, so code branches on it rather than on message text (`23505` unique, `23514` check, `23503` foreign key, `23001` `ON DELETE RESTRICT`).
- **Disaster recovery (DR) test**: rebuilding a system from its backups and code on purpose, so you learn what is missing before a real failure does.
- **Recovery time**: how long a rebuild takes from start to working; the target for it is called RTO (Recovery Time Objective).
- **Preflight check**: a cheap check run before a destructive step, so a problem stops the work while nothing has been lost.
- **Exit code**: the number a program returns when it ends; 0 means success and anything else means failure, which is how scripts and CI read the result.
- **`$LASTEXITCODE`**: PowerShell's variable holding the exit code of the last native program, such as `ssh` or `vagrant`.
- **`$ErrorActionPreference`**: PowerShell's setting for what happens on an error; `Stop` halts on PowerShell errors but ignores native programs' exit codes.
- **Native command**: in PowerShell, an external program (`ssh.exe`) as opposed to a built-in cmdlet (`Get-ChildItem`).
- **Scriptblock**: PowerShell code in `{ }` held as a value, so a function can receive it and run it later with `&`.
- **Dynamic scope**: PowerShell finds a variable by walking up the call stack, so a called function's variable can hide the caller's variable of the same name.
- **Detached HEAD**: git checked out at a specific commit rather than on a branch, which suits a checkout nobody commits to.
- **SSH `BatchMode`**: makes `ssh` fail instead of asking for a password, so an unattended script cannot hang on a prompt.
- **Helm release**: one installed instance of a chart in a namespace, with a revision number that goes up on each upgrade; `helm list -A` shows them.
- **Helm values**: the settings a chart's templates read; a `values.yaml` overrides the chart's defaults, so ours lists only the differences.
- **PersistentVolumeClaim (PVC)**: a pod's request for storage ("64 Mi, one writer"), which stays valid when the pod is replaced.
- **PersistentVolume (PV)**: the actual piece of storage that satisfies a PVC.
- **StorageClass**: names a way of creating PVs on demand; a PVC picks one by name, so its manifest does not depend on the storage behind it.
- **local-path-provisioner**: creates each PV as a directory on one node's disk; fast and simple, but the data is tied to that node.
- **`WaitForFirstConsumer`**: a StorageClass setting that leaves a PVC `Pending` until a pod uses it, so the volume lands on the node the pod was scheduled to.
- **Reclaim policy**: what happens to a PV when its PVC is deleted; `Delete` removes the data, `Retain` keeps it.
- **`kubectl port-forward`**: tunnels a local port to a Service or pod through the API server, for as long as the command runs.
- **cert-manager**: a Kubernetes controller that creates and renews TLS certificates declared as `Certificate` resources.
- **`ObjectStore` (Barman Cloud plugin)**: a resource naming a bucket, its endpoint and credentials, which a `Cluster` points at for backups.
- **`ScheduledBackup` (CNPG)**: a resource that takes a base backup on a cron schedule; its cron has a leading seconds field.
- **`archive_timeout`**: forces Postgres to finish the current WAL file after this long if anything was written, capping how old unshipped changes can get.
- **Timeline**: a Postgres history branch; a promotion starts a new one, which is the leading number in a WAL file's name, and a `.history` file records the fork.
- **Locale (Postgres)**: decides sort order and what counts as a letter; fixed when the database is created.
- **Trigram**: a run of three characters; `pg_trgm` compares strings by the trigrams they share, which is how it tolerates typos.
- **Deployment**: a Kubernetes resource that keeps N identical pods running and replaces them gradually when the pod template changes.
- **Service (Kubernetes)**: a stable name and virtual IP in front of whichever pods match its selector, so callers never track pod IPs.
- **`HTTPRoute`**: Gateway API resource that sends matching paths to a Service; it attaches to a `Gateway` through `parentRefs`, and the longest matching prefix wins.
- **Kustomize base and overlay**: a base is plain YAML true in every environment; an overlay points at bases and changes only what differs, such as namespace and image tag.
- **`configMapGenerator`**: Kustomize feature that builds a ConfigMap from files and puts a content hash in its name, so a changed file rolls the pods using it.
- **Native sidecar**: an init container with `restartPolicy: Always`; it keeps running, starts before the app containers and stops after them.
- **Startup probe**: a check that holds off liveness until it first passes, so a slow boot is not mistaken for a hang.
- **Argo CD hook**: an annotated resource Argo CD runs at a fixed point in a sync, such as `PreSync`, instead of treating it as ordinary desired state.
- **`kubeconform`**: checks rendered manifests against the Kubernetes API schemas without needing a cluster.
- **`readOnlyRootFilesystem`**: a container security setting that makes the image's files unwritable, so anything written at runtime needs a mounted volume.
- **Smoke test**: a short check against the real deployed system that its main path works at all, run right after a deploy.
- **Resource finalizer (Argo CD)**: a marker on an `Application` that makes deleting it also delete everything it deployed; left off here so the app survives.
- **Router factory**: a function that builds a FastAPI `APIRouter` from parameters, so several resources with the same rules share one implementation.
- **`LEFT JOIN LATERAL`**: a join whose subquery can read the current outer row, so it runs once per row; `LEFT` keeps rows where it finds nothing.
- **Upsert (`ON CONFLICT`)**: one `INSERT` that updates the existing row on a key clash, so two racing creates cannot both fail or both insert.
- **`RETURNING old`**: Postgres 18 syntax exposing a row as it was before the write; `old.id IS NULL` means the statement inserted.
- **`SELECT ... FOR UPDATE`**: reads a row and locks it until the transaction ends, so concurrent writers of that row wait their turn.
- **Check-then-act race**: two requests both pass a check before either writes, which is why a unique index, not the check, has the final say.
- **URN**: a URI that names something without being fetchable, such as `urn:health-tracker:problem:near-duplicate`.
- **Mutation check**: breaking a line on purpose to confirm a test fails; a test that stays green was not protecting that line.
- **Netfilter**: the Linux kernel's packet-filtering framework, a set of hooks such as `input` and `forward` that rules attach to.
- **nftables**: the current rule language for netfilter, with tables, chains and rules managed by the `nft` command; it replaces iptables syntax.
- **tc ingress**: the kernel's traffic-control hook for arriving packets; it runs before netfilter, so an eBPF program there can forward a packet netfilter never sees.
- **TPROXY**: a netfilter target that hands a packet to a local proxy without rewriting its destination, which is how Gateway traffic reaches Envoy.
- **NodePort**: a Service port opened on every node, in the range 30000-32767, so traffic to any node reaches the Service.
- **conntrack**: the kernel's table of tracked connections, which lets a firewall accept replies with `ct state established`.
- **Defense in depth**: layering independent controls, so one gap or bug does not expose everything behind it.
- **Prune (Argo CD)**: during a sync, delete tracked resources that no longer exist in git; without it they stay in the cluster and the app shows `OutOfSync`.
- **Sync retry (Argo CD)**: an automated sync that fails runs again, 5 times by default, before it ends as `Failed`; each attempt re-creates the hook Jobs.
- **Client-side routing**: the page's JavaScript maps the URL to a screen without asking the server for a new page; nginx only has to serve `index.html` for any path.
- **Bearer token**: a secret sent in the `Authorization` header; whoever holds it is let in, so anyone who reads it can act as you.
- **`localStorage`**: per-origin browser storage that survives restarts; any script running on the page can read it, which is why it is a poor home for a secret on a page with untrusted scripts.
- **XSS (cross-site scripting)**: an attacker's script running inside your page, with the same access to `localStorage` and the API as your own code.
- **Middleware (`openapi-fetch`)**: a function every request and response passes through, so a concern like auth lives in one place instead of in every call.
- **`useSyncExternalStore`**: the React hook that re-renders a component when state held outside React changes.
- **Query cache (TanStack Query)**: API responses kept in memory under a key, so screens share one result instead of each fetching it.
- **`staleTime`**: how long a cached response counts as fresh; within it a remounted screen uses the cache without refetching.
- **Transactional boundary**: the set of statements that commit or roll back as one; here one `PUT` covers the Meal row and all its Food Entries, so no reader sees half a Meal.
- **Replace semantics**: a `PUT` body is the whole new state, so anything left out is removed, unlike `PATCH`, which changes only what it names.
- **Correlated subquery**: a subquery that refers to the outer row and so runs once per row; here it counts the Day's earlier Meals to derive a Meal's number.
- **Discriminated union**: several object shapes told apart by one field's value (`kind`), so validation and the OpenAPI schema pick the right shape without guessing.
- **N+1 query**: one query for a list, then one more per item; the fix is one extra query for all items, as `load_food_entries` does.
- **Mutation check**: break the code on purpose and confirm a test fails; a mutation that survives marks behavior no test covers.
- **Failure domain**: the set of things that fail together, such as every pod on one worker.
- **Fate sharing**: placing a component with something it cannot work without, so that it adds no failure of its own; here the operator runs beside the Kubernetes API it depends on.
- **Retryable status code**: a status that says the same request may work later, such as `503`, unlike a `4xx`, where asking again gets the same answer.
- **Window function**: SQL that computes a value per row from related rows without collapsing them, as `GROUP BY` would; `row_number() OVER (PARTITION BY day ORDER BY occurred_at, id)` numbers the Sets within each Day.
- **Tie-break column**: a unique column added last to a sort, so rows with equal sort values still have one fixed order; without it a keyset page can skip or repeat them.
- **DST (daylight saving time)**: a timezone's offset changing twice a year, so one local hour is repeated in autumn and one skipped in spring; this is why the moment is stored as an instant and not as local clock time.
- **Optimistic update**: showing a write as done before the server answers, then undoing it if the server refuses; the screen feels instant, at the price of a rollback path.
- **Rollback by inverse**: undoing one failed write by reversing only that write, not by restoring a saved copy of the list, which would also erase other writes made since.
- **Mutation (TanStack Query)**: a write, tracked with its own pending, error and success state, as a query tracks a read.
- **Mutation scope**: a TanStack Query label that makes writes sharing it run one at a time, in order.
- **Query invalidation**: marking cached data as out of date so it is fetched again, which replaces an optimistic guess with the server's answer.
- **Modal**: a layer that blocks the page behind it until closed, keeping keyboard focus and screen readers inside.
- **Focus trap**: keeping keyboard focus inside a modal, so Tab cannot reach the hidden page behind it.
- **Visual viewport**: the part of the page actually visible, which shrinks when a phone's keyboard opens, unlike the layout viewport.
- **`visibilitychange`**: the browser event fired when a page is hidden or shown again, such as when an app returns from the background.
