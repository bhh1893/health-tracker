# Terms

Tech terms defined while teaching, one line each. Domain language lives in `GLOSSARY.md`.

- **Modular monolith**: one deployable service whose code is split into internal modules that talk only through defined interfaces.
- **Distributed monolith**: separately deployed services that still must change and deploy together, paying microservice costs without the benefits.
- **Conway's law**: systems tend to mirror the communication structure of the org that builds them.
- **Origin**: scheme + host + port of a URL (`https://app.example.com:443`); the unit browsers use for security isolation.
- **Same-origin policy**: browser rule that blocks a page's JavaScript from reading responses from a different origin unless that server opts in.
- **CORS** (Cross-Origin Resource Sharing): the opt-in headers a server sends to let pages from other origins call it.
- **Path routing**: a gateway rule that picks the backend service by URL path, e.g. `/api/*` to one service and `/` to another.
- **Three-tier architecture**: presentation (web client), application (API), and data (database) layers, each deployed and scaled separately.
- **Platform component**: infrastructure the app depends on but the team configures rather than writes (gateway, database, cert-manager).
- **Schema migration**: a versioned, ordered script that changes the database schema (add table, add column) so every environment converges on the same shape.
- **Alembic**: the standard migration tool for SQLAlchemy (Python); each migration is a file with `upgrade()` and optional `downgrade()`.
- **Kubernetes Job**: a resource that runs a pod to completion once (exit 0 = success) instead of keeping it running like a Deployment.
- **Rolling update**: Kubernetes' default deploy, replacing old pods with new ones gradually, so old and new code run at the same time for a while.
- **Expand/contract** (parallel change): make schema changes in backward-compatible steps (expand, migrate code, then contract) so old and new code both work mid-rollout.
- **Shared database anti-pattern**: several services reading/writing the same tables, which couples them through the schema.
- **`.gitattributes`**: a committed file that tells Git how to treat paths (line endings, binary vs text, diff drivers) the same way on every machine.
- **`core.autocrlf`**: a per-machine Git setting that converts LF to CRLF on checkout; `.gitattributes` overrides it so the repo, not each laptop, decides.
- **UUIDv7**: a 128-bit ID whose leading bits are a timestamp, so it is unguessable yet sorts roughly by creation time (index-friendly, unlike random UUIDv4).
- **IDOR** (Insecure Direct Object Reference): a bug where changing an ID in a URL lets one user read or edit another user's row because ownership is not checked.
- **Single-table inheritance**: storing several related entity kinds in one table with a type column and nullable columns for each kind.
- **Polymorphic table**: one table holding rows of several kinds (e.g. all Catalog items with a `type` column); foreign keys can no longer guarantee they point at the right kind.
- **IANA timezone**: a named region with its full DST history, e.g. `America/Los_Angeles`; unlike a fixed offset like `-08:00`, it stays correct across daylight saving changes.
- **Generated column**: a column Postgres computes from other columns on write; only immutable expressions are allowed.
- **Soft delete**: marking a row deleted (`deleted_at`) instead of removing it; every query must then filter it out.
- **`ON DELETE CASCADE` / `RESTRICT`**: foreign key rules: deleting the parent deletes children automatically, or the database refuses while children exist.
- **CHECK constraint**: a boolean rule the database evaluates on every insert/update, rejecting rows that violate it.
- **Composite foreign key**: a foreign key over several columns, e.g. `(meal_id, meal_kind)` referencing `meals(id, kind)`, used to enforce cross-table rules.
- **Normalization**: structuring tables so each fact is stored once; duplication is only a problem when copies must stay in sync.
- **Denormalization**: deliberately storing a derivable fact a second time (e.g. a Sessions table) for speed or convenience, at the cost of keeping the copies in sync.
- **Materialized view**: a query result Postgres stores as a table and refreshes on demand; the read-speed step before hand-maintained denormalized tables.
- **Row-Level Security (RLS)**: Postgres policies that automatically filter which rows a session can read or write, e.g. only rows whose `user_id` matches the current user.
- **Immutable function**: a Postgres function guaranteed to return the same output for the same input forever; only these may feed generated columns and indexes.
- **Docker build context**: the directory sent to `docker build`; the Dockerfile cannot read files outside it.
- **Drift check**: a CI step that regenerates an artifact (e.g. `openapi.json`) and fails if it differs from the committed copy.
- **Helm**: the Kubernetes package manager; a chart is templated YAML plus a `values.yaml`, installed as a versioned release.
- **Kustomize**: built into `kubectl`; applies per-environment patches (overlays) to plain-YAML manifests (a base) without templating.
- **GitOps**: an in-cluster agent (e.g. Argo CD) continuously pulls the cluster to match what is committed in Git, instead of CI pushing changes in.
- **Rancher**: SUSE's platform for provisioning and managing many Kubernetes clusters from one UI.
- **Control plane**: the Kubernetes components that run the cluster (API server, scheduler, controller manager, etcd); workers run the app pods.
- **etcd quorum**: etcd needs a majority of members alive to accept writes; 3 members tolerate 1 failure, 1 member tolerates none.
- **Taint / toleration**: a taint on a node repels pods; only pods with a matching toleration may schedule there (kubeadm taints the control plane by default).
- **NAT NIC (VirtualBox)**: gives a VM outbound internet through the host; nothing can connect in. Vagrant requires it as NIC 1.
- **Host-only NIC (VirtualBox)**: a private network visible only to the host and its VMs (here `192.168.56.0/24`).
- **Bridged NIC (VirtualBox)**: puts the VM directly on the physical LAN as its own device, reachable from other machines such as a phone.
- **CIDR**: an IP range written as base/prefix length; `10.244.0.0/16` fixes the first 16 bits, giving 65,536 addresses.
- **Overcommit**: allocating more virtual resources than physically exist; safe for CPU (idle VMs yield it), risky for RAM (it cannot be reclaimed quickly).
- **Node eviction**: the kubelet killing pods when a node runs low on memory or disk, to protect the node itself.
- **L2 announcement**: a node answering ARP requests for a LoadBalancer IP so other LAN devices send traffic for that IP to it (Cilium's MetalLB-style feature).
- **Provisioning**: turning a blank machine into a configured one (packages, settings, services).
- **Ansible control node**: the machine that runs `ansible-playbook` and connects over SSH to the managed hosts (here, the dev VM).
- **Ansible inventory**: the file listing managed hosts, their groups (e.g. `workers`), and how to reach them.
- **Ansible role**: a reusable bundle of tasks, templates and defaults for one concern (e.g. `containerd`), composed by a playbook.
- **Idempotent**: running an operation twice leaves the system the same as running it once; for Ansible, the second run reports `changed=0`.
- **cloud-init**: the standard first-boot hook on cloud VMs that injects SSH keys and runs a short bootstrap script.
- **kubeadm join token**: a short-lived bearer token a new node presents to the control plane to join the cluster.
- **`StrictHostKeyChecking=accept-new`**: SSH trusts a host's key the first time it is seen and refuses if that key later changes.
- **`apt-mark hold`**: pins an installed Debian/Ubuntu package so automatic or manual upgrades skip it; `dpkg_selections` is the Ansible way to set it.
- **Kubespray**: the Kubernetes SIGs Ansible project that installs production kubeadm clusters; highly configurable.
- **Molecule**: a framework for testing Ansible roles in throwaway containers or VMs.
- **StatefulSet**: a Kubernetes workload whose pods keep a stable name and their own volume across restarts.
- **Operator**: an in-cluster controller that runs one piece of software for you (failover, backups, upgrades) from a declared desired state.
- **CRD** (Custom Resource Definition): a new object type added to the Kubernetes API, e.g. CNPG's `Cluster`, that an operator watches.
- **CloudNativePG (CNPG)**: the CNCF Postgres operator; handles replication, failover, backups to object storage and point-in-time restore.
- **Streaming replica**: a read-only Postgres copy that replays the primary's WAL as it is written.
- **Failover**: promoting a replica to primary when the primary is lost.
- **WAL** (write-ahead log): the journal Postgres writes before changing data files; used for crash recovery, replication and point-in-time restore.
- **Pod anti-affinity**: a scheduling rule that keeps matching pods off the same node; "required" makes it a hard rule.
- **Shared-nothing replication**: each database instance keeps its own local disk and the database itself copies data between them, instead of sharing network storage.
- **CPU limit throttling**: a container with a CPU limit is paused when it hits the limit, even if the node has idle CPU.
- **`shared_buffers`**: Postgres' in-memory cache of table and index pages.
- **PgBouncer**: a lightweight proxy that multiplexes many client connections onto a few Postgres connections.
- **Barman Cloud**: the tool CNPG uses to ship base backups and WAL to S3-compatible object storage.
- **Aggregate**: a cluster of objects always read and written together as one unit through its root (a Meal and its Food Entries), so its rules are checked in one place.
- **Debounce**: wait until input pauses (e.g. 150 ms after the last keystroke) before acting, so fast typing sends one request instead of many.
- **Typeahead**: suggestions that update as the user types.
- **Trigram**: a 3-character chunk of text; `pg_trgm` ranks strings by how many trigrams they share, which tolerates typos.
- **Subsequence matching**: fzf-style fuzzy match where the query's letters appear in order but not adjacent ("chkbrst" finds "chicken breast").
- **Inverted index**: a search-engine structure mapping each term to the documents containing it; the core of Lucene and OpenSearch.
- **Dual write**: writing the same change to two systems (e.g. Postgres and a search engine) and keeping them in sync; breaks when one write succeeds and the other fails.
- **Keyset (cursor) pagination**: fetch the next page as "rows after this sort key" instead of "skip N rows"; stable under inserts and fast at any depth.
- **RFC 9457 Problem Details**: a standard JSON error body (`type`, `title`, `status`, `detail`) served as `application/problem+json`.
- **"/me" pattern**: the API infers the caller from their credentials instead of taking a user ID in the URL.
- **Optimistic concurrency**: a write carries the version it read (`If-Match: <ETag>`); the server refuses with `412` if someone changed it since.
- **ETag**: a response header holding an opaque version tag of a resource.
- **Liveness probe**: a Kubernetes check that the process is alive; failing it restarts the container.
- **Readiness probe**: a Kubernetes check that the pod can serve traffic; failing it removes the pod from Service endpoints without restarting it.
- **`operationId`**: the unique, stable name of one endpoint in an OpenAPI schema; code generators and MCP wrappers use it as the function or tool name.
- **Additive change**: an API change old clients safely ignore (new optional field, new endpoint); removing or renaming something is breaking.
- **SPA (single-page app)**: the browser loads one HTML page and a JS bundle once; JS draws every screen and fetches data as JSON.
- **TypeScript**: JavaScript plus type annotations checked at build time, then stripped to plain JS.
- **React**: a UI library where components describe what the screen should look like for the current state, and React updates the DOM to match.
- **Vite**: a front-end build tool: a fast dev server, plus a production bundler that emits static files.
- **`openapi-typescript` / `openapi-fetch`**: the first turns `openapi.json` into a TypeScript types file; the second is a tiny `fetch` wrapper that type-checks every call against it.
- **Multi-stage Dockerfile**: one stage builds (with compilers, Node), a later stage copies only the output, so build tools never ship in the final image.
- **Content-hashed assets**: build output named by a hash of its contents (`app.3f9a1c.js`), so it can be cached forever; a change gets a new name.
- **SPA fallback**: the web server answers any unknown path with `index.html` so client-side routes survive a refresh or a bookmark.
- **Client-side routing**: the JS app maps URLs to screens and changes the URL without a page load (React Router).
- **TanStack Query**: a library that fetches, caches, retries and refetches server data, so components don't hand-manage loading and error state.
- **PWA (progressive web app)**: a website that can be installed to the home screen and, with a service worker, work offline.
- **Web app manifest**: a JSON file giving a site its home-screen name, icon and full-screen launch.
- **Service worker**: a background script the browser runs for a site; it can intercept requests to serve offline or queue writes.
- **ESLint / Prettier**: a linter that flags bug-prone code, and a formatter that rewrites code to one style so diffs show only real changes.
- **Headless UI library**: components that supply behaviour, keyboard handling and screen-reader roles but no styling (React Aria).
- **React Aria Components**: Adobe's headless React library for accessible widgets (combobox, dialog, listbox); exposes state as `data-*` attributes to style against.
- **Utility-first CSS (Tailwind)**: styling with many small single-purpose classes in the markup (`rounded-xl px-3`) instead of a separate stylesheet per component.
- **Combobox**: a text input joined to a suggestion list, with a defined keyboard and screen-reader pattern (WAI-ARIA).
- **Bottom sheet**: a panel that slides up from the bottom of a phone screen over the current page; the mobile form of a dialog.
- **Secure context**: a page served over HTTPS or from `localhost`; browsers expose some APIs (`crypto.randomUUID`, clipboard, service workers) only there.
- **HMR (hot module replacement)**: the dev server swaps a changed module into the running page without a full reload; it relies on a file watcher noticing every save.
- **Out-of-order responses**: a slower, older request answering after a newer one; a search box must discard it or show stale results.
- **tmux**: a terminal multiplexer: split panes and windows inside one terminal, in sessions that keep running after you disconnect.
- **VS Code Remote-SSH**: an extension that runs VS Code's backend on a remote machine over SSH, so the editor on Windows edits files on the VM.
- **SSHFS**: mounts a remote machine's folder over SSH so it looks like a local drive; convenient but slower and weaker at file watching.
- **`connection: local` (Ansible)**: Ansible runs tasks directly on the machine it is invoked on instead of over SSH.
- **uv / `uv.lock`**: Astral's fast Python package and version manager; installs Python itself from a `.python-version` file, and the lockfile records the exact version and hash of every dependency.
- **SSH agent forwarding**: a remote machine borrows the keys in your local SSH agent for the life of the connection, so no key is stored remotely.
- **GNU Stow**: a symlink manager; each package folder mirrors `$HOME`, and `stow <pkg>` links every file to the same path under `$HOME`.
- **Runbook**: a written step-by-step procedure for an operational task, for whoever runs it next (often you, months later).
- **Gateway API**: the Kubernetes standard for routing outside traffic into the cluster: a `Gateway` (listener on a port/IP) plus `HTTPRoute`s (path/header rules to Services); Cilium implements it with Envoy.
- **Sidecar**: a second container in the same Pod as the app, sharing its network (`localhost`); used to add a concern (auth, proxying, logging) without changing the app.
- **Bearer token**: a secret sent as `Authorization: Bearer <token>`; whoever holds the token is let in.
- **HTTP Basic Auth**: browser-native username/password prompt sent as a base64 header; unreliable in iOS home-screen apps.
- **ext_authz**: an Envoy filter that asks an external service to allow or deny each request before it is forwarded.
- **WireGuard (Cilium transparent encryption)**: encrypts pod-to-pod traffic between nodes with a kernel VPN, enabled by one Cilium setting; no certificates or app changes.
- **mTLS**: both sides of a connection present certificates, so each proves its identity as well as encrypting traffic.
- **`BackendTLSPolicy`**: Gateway API object that makes the Gateway use TLS to the backend Service, verifying its certificate.
- **HSTS**: a response header telling a browser to use only HTTPS for a host for a set time; a broken certificate then cannot be clicked through.
- **DNS rebinding protection**: a router feature that drops DNS answers pointing at private IPs; can break "public name, LAN address" setups.
- **DNS-01 challenge**: Let's Encrypt proves you own a domain by checking a TXT record in its DNS, so no public server is needed.
- **`RequestRedirect` (Gateway API)**: an `HTTPRoute` filter that answers with a redirect, used for HTTP to HTTPS.
- **WAL (write-ahead log)**: Postgres writes every change to a sequential log before the data files; shipping this log elsewhere is how you copy the database continuously.
- **Base backup**: a full copy of the database files at one moment; restorable only together with the WAL written after it.
- **PITR (point-in-time recovery)**: restoring a base backup and replaying WAL up to a chosen timestamp, e.g. just before a mistake.
- **WAL archiving**: continuously copying finished WAL segments to backup storage (roughly every minute under light load).
- **Object storage**: stores whole files ("objects") under a key in a flat bucket, read and written over HTTP; no directories, no editing in place.
- **Bucket**: a named container of objects; access keys are granted per bucket.
- **Garage**: software that serves an S3-compatible object storage API from a plain disk; here the backup target on the dev VM.
- **MinIO**: the object store first chosen here; its open-source edition was archived, so Garage replaced it (ADR 0011).
- **Garage layout**: the record of which nodes store data and their share of it; nothing works until one is applied.
- **systemd unit**: a small file telling Linux's service manager how to run a program, restart it and start it at boot.
- **fsync**: forces written data from memory onto the disk, so a power cut cannot lose it; slower, but safe.
- **`no_log`**: tells Ansible not to print a task's values, so secrets stay out of its output.
- **S3-compatible**: speaks Amazon S3's HTTP API, so tools written for S3 work against Garage, B2, R2 or AWS by changing endpoint and credentials.
- **Barman Cloud plugin**: CNPG's plugin that sends base backups and WAL to S3-compatible storage and restores from it.
- **`serverName` (CNPG)**: the folder name a cluster uses in the backup bucket; a recovered cluster needs a new one, since two histories cannot share a folder.
- **Recovery bootstrap (CNPG)**: creating a new `Cluster` from a backup instead of an empty database; only possible at creation, never in place.
- **Retention policy**: how long backups are kept before the operator deletes them (7 days here).
- **Restore drill**: deliberately restoring from backup to prove it works before you need it.
- **btree index**: Postgres's default index, a sorted tree; serves equality, ranges and `ORDER BY` when the column order matches the query, and can be read backwards.
- **Composite index and column order**: one index over several columns, usable only left to right; `(user_id, day, occurred_at)` serves `user_id`, then `user_id + day`, but not `day` alone.
- **Index-only scan / `INCLUDE`**: extra columns stored in the index leaf so a query can be answered without touching the table.
- **Foreign keys are not auto-indexed (Postgres)**: the child column needs its own index, or joins and cascading deletes scan the whole table.
- **`EXPLAIN (ANALYZE, BUFFERS)`**: runs the query and prints the chosen plan with real timings and page reads; the evidence that an index is used.
- **Trigram (`pg_trgm`)**: a 3-letter chunk of a string; strings sharing many trigrams are similar, which gives typo-tolerant matching.
- **GIN vs GiST**: two index types for composite values like trigrams; GIN looks up faster, GiST is larger but can return nearest matches in order.
- **`similarity` vs `word_similarity`**: whole-string vs "does the query match part of the name" scoring; typeahead needs the second, duplicate checks the first.
- **`SET LOCAL`**: changes a Postgres setting for the current transaction only, used for per-query trigram thresholds.
- **Seed data**: deterministic synthetic rows loaded to make query plans realistic when real data is too small.
- **URL state**: keeping a view's parameters (such as the viewed Day) in the address (`?day=...`) rather than in memory, so reload, back button and links from other screens land in the same place.
- **Deep link**: a URL that opens the app directly at a specific screen and state, e.g. a Day.
- **Disclosure row (accordion)**: a collapsed summary row that expands in place on tap to show its detail, keeping long lists short.
- **Native date picker**: `<input type="date">`, which the phone renders as its own OS date chooser, so we write no calendar widget.
- **Integration test**: exercises several real parts together (here HTTP handler, SQL and a real Postgres) instead of mocking the neighbors.
- **Unit test**: tests one pure function in isolation; cheap, but blind to how pieces connect.
- **Testcontainers**: a library that starts a throwaway Docker container (here Postgres 18) from inside the test run and removes it afterward.
- **Test transaction rollback**: each test runs inside a database transaction that is rolled back at the end, so tests stay isolated without re-creating the schema.
- **MSW (Mock Service Worker)**: intercepts network calls in tests and returns canned responses, so UI tests need no real server.
- **Schemathesis**: reads an OpenAPI file and generates many requests to check every endpoint matches its schema and never crashes.
- **Smoke test**: a tiny post-deploy check that the core path works on the real system.
- **kubeconform**: validates Kubernetes manifests against the official schemas without needing a cluster.
- **Required status check / `ci-gate`**: branch protection blocks merges until named checks pass; one always-running gate job avoids path-filtered checks hanging as pending.
- **Flaky test**: a test that sometimes fails with no code change; erodes trust in CI, so it is fixed or removed.
- **Threat model**: a short list of who or what you defend against and what you deliberately do not; it decides how much security machinery is justified.
- **`kubectl create --dry-run=client -o yaml | kubectl apply -f -`**: renders an object locally and applies it, turning an imperative `create` into a re-runnable step that reports `unchanged`.
- **argv**: a process's command-line arguments; any user on the machine can read them with `ps`, so secrets never go there.
- **`kubernetes.io/basic-auth`**: a Secret type the API server checks for a `username` or `password` key; CNPG requires it for role passwords.
- **Kubernetes Secret**: a cluster object holding sensitive values for pods to read as env vars or files; base64-encoded, which is an encoding, not encryption.
- **etcd encryption at rest**: an API server setting that encrypts Secrets inside etcd; off by default, and skipped here because reaching etcd already takes host access.
- **Least privilege**: give each component only the access it needs, so a bug or breach in it can do limited damage.
- **DDL vs DML**: SQL that changes the schema (`CREATE`, `DROP`) vs SQL that changes rows (`INSERT`, `UPDATE`, `DELETE`).
- **`ALTER DEFAULT PRIVILEGES`**: tells Postgres which grants to apply automatically to tables a given role creates later.
- **SOPS + age**: SOPS encrypts values inside YAML files so they can be committed; age is the small encryption tool that holds the key.
- **SealedSecrets**: a cluster controller that decrypts secrets committed to git, using a private key held in that cluster.
- **External Secrets Operator**: a controller that copies values from an outside store (AWS, Azure, Vault) into Kubernetes Secrets.
- **Secret rotation**: replacing a secret with a new value so the old one stops working.
- **`CreateContainerConfigError`**: a pod state meaning a Secret or ConfigMap it needs is missing; Kubernetes keeps retrying, so it recovers once the object exists.
- **`managed.roles` (CNPG)**: Postgres roles declared on the `Cluster` itself, which the operator creates and regularly compares with the database.
- **`DatabaseRole` (CNPG)**: a separate resource for one role, applied only when it or its Secret changes.
- **`cnpg.io/reload` label**: marks a Secret so CNPG applies changes to it immediately rather than at a later reconciliation.
- **Guardrail vs boundary**: a guardrail stops accidents but can be stepped around; a boundary is enforced, such as by a separate user account.
- **Push vs pull deploy**: push means an outside system runs `kubectl apply` against the cluster; pull means an agent inside the cluster fetches changes, so no outside system needs cluster credentials.
- **Argo CD**: the GitOps agent that watches a git path and applies it to the cluster.
- **Argo CD `Application`**: one Argo resource saying "keep this git path synced to this namespace".
- **Auto-sync / self-heal**: Argo applies new commits by itself / reverts manual changes made in the cluster.
- **Sync hooks (`PreSync`, `PostSync`)**: Jobs Argo runs before or after applying the app; the sync waits for them and stops if they fail.
- **`hook-delete-policy: BeforeHookCreation`**: Argo deletes the previous hook Job before creating a new one, so a fixed Job name works every sync.
- **Expand-then-contract migration**: add new schema first and remove old schema in a later deploy, so old and new code both work during a rollout.
- **GHCR**: GitHub Container Registry, which stores container images next to the repo.
- **Image tag vs digest**: a tag is a movable label (`:abc123`); a digest is the immutable content hash.
- **Immutable SHA tag**: tagging an image with its git commit SHA so a tag always means the same build.
- **Branch ruleset / bypass actor**: GitHub rules protecting a branch; a bypass actor is allowed past them (here, deploy keys, ADR 0018).
- **Deploy key**: an SSH key that grants access to a single repo, read-only unless you say otherwise.
- **Drift (GitOps)**: the cluster no longer matches git.
- **Rollback by revert**: undoing a deploy by reverting the git commit, so the same pipeline redeploys the old version.
- **`docker buildx` layer cache**: reuses unchanged image layers between builds to speed up CI.
- **GitHub Actions**: GitHub's built-in automation; a workflow file in `.github/workflows/` runs jobs on GitHub-hosted machines when events like a PR happen.
- **Workflow / job / step**: a workflow is one YAML file; it holds jobs (each on its own fresh runner, in parallel unless chained with `needs`); a job holds steps run in order.
- **`workflow_dispatch`**: a GitHub Actions trigger that lets a person start a workflow by hand; it only works once the workflow file is on the default branch.
- **Runner**: the machine that executes a job (`ubuntu-24.04` is a GitHub-hosted Linux VM, thrown away afterward).
- **Path filter**: a check of which files a PR changed, used to skip jobs that have nothing to do (here via `dorny/paths-filter`).
- **Status check / required check**: a pass/fail result shown on a PR; a required one blocks merge until it passes.
- **`ci-gate`**: our single required check; it always runs and fails only if a job it waits for failed, so skipped jobs never leave the PR stuck "pending".
- **`needs` / `if: always()`**: `needs` makes a job wait for others; by default it is skipped if one of them failed or was skipped, so `always()` forces the gate to run and judge the results itself.
- **Concurrency group**: a label so a newer run of the same workflow cancels the older one.
- **`GITHUB_TOKEN`**: a short-lived credential GitHub creates for each workflow run; its `permissions:` block sets what it can do, and pushes made with it do not start new workflow runs.
- **`paths-ignore`**: a workflow trigger filter; a push that touches only the listed paths starts no run.
- **Bot commit**: a commit made by automation rather than a person; here, CI writing image tags to `main` with a deploy key.
- **GitHub App**: an identity you register with GitHub that gets short-lived tokens from a private key; the usual way to give automation its own login at a company.
- **Pinning an action to a commit**: `uses: owner/action@<full sha>` instead of a tag, because a tag can be moved to different code and a commit cannot.
- **Branch ruleset**: GitHub rules on a branch (require a check, block force-push); on free plans they need a public repo.
- **gitleaks**: a scanner that searches files and git history for strings shaped like secrets (API keys, tokens, private keys).
- **Redaction (`--redact`)**: hiding the matched secret in scan output so the CI log does not leak it a second time.
- **yamllint**: a linter for YAML syntax and style.
- **`.editorconfig`**: a file editors read so every contributor gets the same indentation, line endings and final newline.
- **`.gitignore`**: patterns for files git must never track (secrets, caches, editor state).
- **`fetch-depth: 0` / `--log-opts`**: `fetch-depth: 0` makes the checkout download all history and branches; `--log-opts` tells gitleaks which commit range (a `git log` argument) to scan, so a PR is judged only on its own commits.
- **Vagrant**: a CLI that creates and destroys VMs from a committed text file, so a machine can be rebuilt instead of hand-maintained.
- **Vagrantfile**: the Ruby file describing one or more VMs (image, CPU, RAM, network); Vagrant commands act on the one in the current folder.
- **Vagrant box**: the prebuilt VM image a machine starts from; pinning `box_version` keeps rebuilds on one published release, though only a checksum would prove the bytes match.
- **Vagrant provisioner**: a step Vagrant runs inside the VM after boot (upload a file, run a script); by default only on the first `vagrant up`.
- **Synced folder**: a host folder mounted inside the VM; turned off here so the VM depends on nothing from the host.
- **`.vagrant/`**: Vagrant's per-folder state, linking the folder to its VM and holding that VM's generated SSH private key; never committed.
- **SSH key pair**: a private key that stays secret and a public key placed on servers; a server admits you by checking you hold the private half.
- **ed25519**: the modern, short, fast SSH key type, and the default choice for new keys.
- **Host key / `known_hosts`**: a server's own identity key, and the file where your SSH client remembers it, so an impostor at the same IP gets noticed.
- **`StrictHostKeyChecking accept-new`**: trust a host's key the first time, refuse if it later changes; a rebuilt VM has a new key, so clear the old entry with `ssh-keygen -R`.
- **Git worktree**: a second folder attached to the same repo with its own branch checked out, so two pieces of work do not disturb each other.
- **Ansible playbook**: a YAML file mapping hosts to the roles and tasks to run on them; `dev.yml` is one.

- **deb822 source**: the modern apt repo file format (`/etc/apt/sources.list.d/*.sources`), one block of `URIs`, `Suites`, `Components`, `Signed-By`.

- **apt version pin (`pkg=version`)**: installs that exact package version, so a rebuild does not silently pick up a newer one.
- **`docker` group**: members can use the Docker socket without sudo, which is effectively root on the machine; group changes apply at the next login.
- **Checksum pin**: a committed sha256 of a download, so a changed or tampered file fails the install.
- **Terraform**: a tool that makes a provider's API (cloud VMs, Cloudflare settings) match committed `.tf` files; `plan` shows the changes, `apply` makes them. First used for Cloudflare (ADR 0029); replaces Vagrant when the project moves to a cloud.
- **Multi-machine Vagrantfile**: one file defining several VMs with `config.vm.define`; settings outside the `define` block apply to all of them.
- **`private_network` / `public_network`**: Vagrant's names for a VirtualBox host-only NIC and a bridged NIC.
- **Default route**: where a machine sends traffic for any address it has no more specific route to; normally there should be exactly one.
- **Route metric**: the priority of a route, lower wins; two default routes with equal metrics leave the choice to the order they were added.
- **FastAPI**: a Python web framework that builds routes, validation and the OpenAPI schema from type hints.
- **Pydantic**: a library that validates data against typed Python classes; FastAPI uses it for request and response bodies.
- **Dependency injection (`Depends`)**: a route declares what it needs and FastAPI supplies it, so tests can swap in a replacement through `dependency_overrides`.
- **SQLAlchemy engine / session**: the engine owns the connection pool; a session is one unit of work on a connection.
- **psycopg**: the driver that speaks the Postgres protocol for Python; SQLAlchemy sits on top of it.
- **Savepoint**: a marker inside a transaction that can be rolled back to; it lets code "commit" inside a test whose outer transaction is later undone.
- **Structured logging**: each log line is a JSON object, so tools can filter by field instead of parsing text.
- **`ruff`**: a fast Python linter and formatter.
- **`pyright`**: a static type checker; strict mode rejects anything whose type it cannot determine.
- **ASGI**: the standard interface between a Python async web server and a web app.
- **Uvicorn**: the ASGI server that listens on the port and hands each request to FastAPI.
- **Lifespan**: FastAPI's startup and shutdown hook, used here to create and close the connection pool.
- **TCP keepalive / `tcp_user_timeout`**: keepalives probe an idle connection; `tcp_user_timeout` caps how long sent data may go unacknowledged; both detect a peer that vanished without closing.
- **`ansible.cfg`**: Ansible's settings file, read from the directory you run in; here it names the inventory and SSH options.
- **Ansible collection**: a versioned package of modules from Ansible Galaxy, pinned in `requirements.yml`; `community.general.modprobe` comes from one.
- **`reset_connection`**: closes Ansible's open SSH connection to a host, so the next task connects fresh.
- **`throttle`**: limits how many hosts run a task at once; 1 protects a shared file from parallel writes.
- **Swap**: disk used as overflow RAM; off on nodes by default, because the kubelet's memory accounting assumes memory is real RAM.
- **Kernel module**: code loaded into the running Linux kernel on demand; `modules-load.d` loads it again at boot.
- **sysctl**: a kernel setting changed at run time; files in `/etc/sysctl.d/` reapply it at boot.
- **`overlay`**: the filesystem that stacks image layers into one view, which is how containers share read-only layers.
- **`br_netfilter`**: kernel module that sends traffic crossing a Linux bridge through iptables, so Kubernetes network rules see it.
- **IP forwarding**: lets a machine pass packets between interfaces like a router; off by default, required so pod traffic can cross a node.
- **cgroup**: a kernel feature that limits and measures a group of processes' CPU and memory; v2 is the single unified tree.
- **cgroup driver**: what manages cgroups for containers; containerd and the kubelet must both use `systemd`, the manager that already owns the tree.
- **containerd**: the daemon that pulls images and runs containers; Docker is built on it, but Kubernetes talks to it directly and needs nothing from Docker.
- **CRI (Container Runtime Interface)**: the API the kubelet uses to talk to a runtime such as containerd.
- **runc**: the small program containerd calls to actually start a container process.
- **Netplan**: Ubuntu's network config layer; YAML in `/etc/netplan/`, merged in name order, rendered for systemd-networkd.
- **Router advertisement (RA)**: how an IPv6 router announces itself; hosts that accept it gain an address and a default route, with no DHCP involved.
- **SSH drop-in**: a file in `/etc/ssh/sshd_config.d/`; for most settings sshd keeps the first value it reads, so name order decides who wins.
- **kubeadm preflight**: kubeadm's own checks that a machine is ready to join a cluster; `kubeadm init phase preflight --dry-run` runs them alone.
- **`package-lock.json` / `npm ci`**: the lockfile records the exact version of every direct and indirect dependency; `npm ci` installs precisely that and fails if it disagrees with `package.json`.
- **`engines`**: the `package.json` field naming the Node versions a project supports; `engine-strict` in `.npmrc` turns a mismatch into a failed install.
- **Content hash**: a fingerprint of a file's bytes put in its name (`index-CZaudM2M.js`), so new content means a new URL and old URLs can be cached forever.
- **`Cache-Control: no-cache`**: the browser may store the file but must ask the server if it changed before using it; despite the name, this is not `no-store`.
- **`try_files`**: nginx tries each path in order and serves the first that exists; the last entry is the fallback, a URI or a status such as `=404`.
- **`tsc --noEmit`**: runs the TypeScript compiler as a checker only; Vite strips types without checking them, so this is the only step that catches type errors.
- **jsdom**: a simulated browser DOM in Node, so component tests run without a real browser.
- **Vitest / React Testing Library**: Vite's test runner, and helpers that find elements the way a user does (by role and name), not by internals.
- **`DataView`**: reads and writes numbers at byte offsets in a buffer, big-endian by default; used to lay out the UUIDv7 bytes.
- **`npm audit`**: checks installed packages against known advisories; `--omit=dev` limits it to what ships to users.
- **`kubeadm init` / `join`**: `init` creates the control plane (certificates, API server, etcd) on one node; `join` connects another node's kubelet to it.
- **kubeconfig**: a file holding a cluster's address and a credential; `kubectl` and Helm read `~/.kube/config`. The admin one is full control of the cluster.
- **CNI (Container Network Interface)**: the plugin standard that gives pods their IPs and connectivity; nodes stay NotReady until one is installed. Cilium is ours.
- **kube-proxy**: the default per-node program that implements Services, usually with iptables rules.
- **eBPF**: small verified programs loaded into the running Linux kernel, here to route and load-balance packets without a userspace hop.
- **kube-proxy replacement**: Cilium implementing Services in eBPF, so kube-proxy is not installed.
- **IPAM (IP Address Management)**: how pods get IPs. `ipam.mode: kubernetes` uses the per-node `podCIDR` slices cut from kubeadm's `podSubnet`.
- **ARP**: how a device on a LAN asks "who has this IP?" and learns the MAC address to send to.
- **Gratuitous ARP**: an unprompted ARP announcement that tells neighbours an IP has moved to a new MAC.
- **Lease (Kubernetes)**: a small API object used for leader election; the node holding a Service's lease answers ARP for its IP.
- **Server-side apply**: `kubectl apply --server-side`: the API server merges the change and tracks field ownership, with no size-limited annotation on the object.
- **Expression index**: an index on a computed value such as `lower(name)`; a query uses it only when it repeats the same expression.
- **Covering index**: an index that also stores extra columns (`INCLUDE (meal_id)`), so a query can be answered without visiting the table.
- **Trusted extension**: a Postgres extension that a non-superuser with `CREATE` on the database may install; `pg_trgm` is one.
- **SQLSTATE**: the five-character code Postgres returns with every error; stable, so code branches on it rather than on message text (`23505` unique, `23514` check, `23503` foreign key, `23001` `ON DELETE RESTRICT`).
- **Disaster recovery (DR) test**: rebuilding a system from its backups and code on purpose, so you learn what is missing before a real failure does.
- **Recovery time**: how long a rebuild takes from start to working; the target for it is called RTO (Recovery Time Objective).
- **Preflight check**: a cheap check run before a destructive step, so a problem stops the work while nothing has been lost.
- **Exit code**: the number a program returns when it ends; 0 means success and anything else means failure, which is how scripts and CI read the result.
- **`$LASTEXITCODE`**: PowerShell's variable holding the exit code of the last native program, such as `ssh` or `vagrant`.
- **`$ErrorActionPreference`**: PowerShell's setting for what happens on an error; `Stop` halts on PowerShell errors but ignores native programs' exit codes.
- **Native command**: in PowerShell, an external program (`ssh.exe`) as opposed to a built-in cmdlet (`Get-ChildItem`).
- **Scriptblock**: PowerShell code in `{ }` held as a value, so a function can receive it and run it later with `&`.
- **Dynamic scope**: PowerShell finds a variable by walking up the call stack, so a called function's variable can hide the caller's variable of the same name.
- **Detached HEAD**: git checked out at a specific commit rather than on a branch, which suits a checkout nobody commits to.
- **SSH `BatchMode`**: makes `ssh` fail instead of asking for a password, so an unattended script cannot hang on a prompt.
- **Helm release**: one installed instance of a chart in a namespace, with a revision number that goes up on each upgrade; `helm list -A` shows them.
- **Helm values**: the settings a chart's templates read; a `values.yaml` overrides the chart's defaults, so ours lists only the differences.
- **PersistentVolumeClaim (PVC)**: a pod's request for storage ("64 Mi, one writer"), which stays valid when the pod is replaced.
- **PersistentVolume (PV)**: the actual piece of storage that satisfies a PVC.
- **StorageClass**: names a way of creating PVs on demand; a PVC picks one by name, so its manifest does not depend on the storage behind it.
- **local-path-provisioner**: creates each PV as a directory on one node's disk; fast and simple, but the data is tied to that node.
- **`WaitForFirstConsumer`**: a StorageClass setting that leaves a PVC `Pending` until a pod uses it, so the volume lands on the node the pod was scheduled to.
- **Reclaim policy**: what happens to a PV when its PVC is deleted; `Delete` removes the data, `Retain` keeps it.
- **`kubectl port-forward`**: tunnels a local port to a Service or pod through the API server, for as long as the command runs.
- **cert-manager**: a Kubernetes controller that creates and renews TLS certificates declared as `Certificate` resources.
- **`ObjectStore` (Barman Cloud plugin)**: a resource naming a bucket, its endpoint and credentials, which a `Cluster` points at for backups.
- **`ScheduledBackup` (CNPG)**: a resource that takes a base backup on a cron schedule; its cron has a leading seconds field.
- **`archive_timeout`**: forces Postgres to finish the current WAL file after this long if anything was written, capping how old unshipped changes can get.
- **Timeline**: a Postgres history branch; a promotion starts a new one, which is the leading number in a WAL file's name, and a `.history` file records the fork.
- **Locale (Postgres)**: decides sort order and what counts as a letter; fixed when the database is created.
- **Trigram**: a run of three characters; `pg_trgm` compares strings by the trigrams they share, which is how it tolerates typos.
- **Deployment**: a Kubernetes resource that keeps N identical pods running and replaces them gradually when the pod template changes.
- **Service (Kubernetes)**: a stable name and virtual IP in front of whichever pods match its selector, so callers never track pod IPs.
- **`HTTPRoute`**: Gateway API resource that sends matching paths to a Service; it attaches to a `Gateway` through `parentRefs`, and the longest matching prefix wins.
- **Kustomize base and overlay**: a base is plain YAML true in every environment; an overlay points at bases and changes only what differs, such as namespace and image tag.
- **`configMapGenerator`**: Kustomize feature that builds a ConfigMap from files and puts a content hash in its name, so a changed file rolls the pods using it.
- **Native sidecar**: an init container with `restartPolicy: Always`; it keeps running, starts before the app containers and stops after them.
- **Startup probe**: a check that holds off liveness until it first passes, so a slow boot is not mistaken for a hang.
- **Argo CD hook**: an annotated resource Argo CD runs at a fixed point in a sync, such as `PreSync`, instead of treating it as ordinary desired state.
- **`readOnlyRootFilesystem`**: a container security setting that makes the image's files unwritable, so anything written at runtime needs a mounted volume.
- **Resource finalizer (Argo CD)**: a marker on an `Application` that makes deleting it also delete everything it deployed; left off here so the app survives.
- **Router factory**: a function that builds a FastAPI `APIRouter` from parameters, so several resources with the same rules share one implementation.
- **`LEFT JOIN LATERAL`**: a join whose subquery can read the current outer row, so it runs once per row; `LEFT` keeps rows where it finds nothing.
- **Upsert (`ON CONFLICT`)**: one `INSERT` that updates the existing row on a key clash, so two racing creates cannot both fail or both insert.
- **`RETURNING old`**: Postgres 18 syntax exposing a row as it was before the write; `old.id IS NULL` means the statement inserted.
- **`SELECT ... FOR UPDATE`**: reads a row and locks it until the transaction ends, so concurrent writers of that row wait their turn.
- **Check-then-act race**: two requests both pass a check before either writes, which is why a unique index, not the check, has the final say.
- **URN**: a URI that names something without being fetchable, such as `urn:health-tracker:problem:near-duplicate`.
- **Mutation check**: breaking a line on purpose to confirm a test fails; a test that stays green was not protecting that line.
- **Netfilter**: the Linux kernel's packet-filtering framework, a set of hooks such as `input` and `forward` that rules attach to.
- **nftables**: the current rule language for netfilter, with tables, chains and rules managed by the `nft` command; it replaces iptables syntax.
- **tc ingress**: the kernel's traffic-control hook for arriving packets; it runs before netfilter, so an eBPF program there can forward a packet netfilter never sees.
- **TPROXY**: a netfilter target that hands a packet to a local proxy without rewriting its destination, which is how Gateway traffic reaches Envoy.
- **NodePort**: a Service port opened on every node, in the range 30000-32767, so traffic to any node reaches the Service.
- **conntrack**: the kernel's table of tracked connections, which lets a firewall accept replies with `ct state established`.
- **Defense in depth**: layering independent controls, so one gap or bug does not expose everything behind it.
- **Prune (Argo CD)**: during a sync, delete tracked resources that no longer exist in git; without it they stay in the cluster and the app shows `OutOfSync`.
- **Sync retry (Argo CD)**: an automated sync that fails runs again, 5 times by default, before it ends as `Failed`; each attempt re-creates the hook Jobs.
- **Client-side routing**: the page's JavaScript maps the URL to a screen without asking the server for a new page; nginx only has to serve `index.html` for any path.
- **`localStorage`**: per-origin browser storage that survives restarts; any script running on the page can read it, which is why it is a poor home for a secret on a page with untrusted scripts.
- **XSS (cross-site scripting)**: an attacker's script running inside your page, with the same access to `localStorage` and the API as your own code.
- **Middleware (`openapi-fetch`)**: a function every request and response passes through, so a concern like auth lives in one place instead of in every call.
- **`useSyncExternalStore`**: the React hook that re-renders a component when state held outside React changes.
- **Query cache (TanStack Query)**: API responses kept in memory under a key, so screens share one result instead of each fetching it.
- **`staleTime`**: how long a cached response counts as fresh; within it a remounted screen uses the cache without refetching.
- **Transactional boundary**: the set of statements that commit or roll back as one; here one `PUT` covers the Meal row and all its Food Entries, so no reader sees half a Meal.
- **Replace semantics**: a `PUT` body is the whole new state, so anything left out is removed, unlike `PATCH`, which changes only what it names.
- **Correlated subquery**: a subquery that refers to the outer row and so runs once per row; here it counts the Day's earlier Meals to derive a Meal's number.
- **Discriminated union**: several object shapes told apart by one field's value (`kind`), so validation and the OpenAPI schema pick the right shape without guessing.
- **N+1 query**: one query for a list, then one more per item; the fix is one extra query for all items, as `load_food_entries` does.
- **Mutation check**: break the code on purpose and confirm a test fails; a mutation that survives marks behavior no test covers.
- **Failure domain**: the set of things that fail together, such as every pod on one worker.
- **Fate sharing**: placing a component with something it cannot work without, so that it adds no failure of its own; here the operator runs beside the Kubernetes API it depends on.
- **Retryable status code**: a status that says the same request may work later, such as `503`, unlike a `4xx`, where asking again gets the same answer.
- **Window function**: SQL that computes a value per row from related rows without collapsing them, as `GROUP BY` would; `row_number() OVER (PARTITION BY day ORDER BY occurred_at, id)` numbers the Sets within each Day.
- **Tie-break column**: a unique column added last to a sort, so rows with equal sort values still have one fixed order; without it a keyset page can skip or repeat them.
- **DST (daylight saving time)**: a timezone's offset changing twice a year, so one local hour is repeated in autumn and one skipped in spring; this is why the moment is stored as an instant and not as local clock time.
- **Optimistic update**: showing a write as done before the server answers, then undoing it if the server refuses; the screen feels instant, at the price of a rollback path.
- **Rollback by inverse**: undoing one failed write by reversing only that write, not by restoring a saved copy of the list, which would also erase other writes made since.
- **Mutation (TanStack Query)**: a write, tracked with its own pending, error and success state, as a query tracks a read.
- **Mutation scope**: a TanStack Query label that makes writes sharing it run one at a time, in order.
- **Query invalidation**: marking cached data as out of date so it is fetched again, which replaces an optimistic guess with the server's answer.
- **Modal**: a layer that blocks the page behind it until closed, keeping keyboard focus and screen readers inside.
- **Focus trap**: keeping keyboard focus inside a modal, so Tab cannot reach the hidden page behind it.
- **Visual viewport**: the part of the page actually visible, which shrinks when a phone's keyboard opens, unlike the layout viewport.
- **`visibilitychange`**: the browser event fired when a page is hidden or shown again, such as when an app returns from the background.
- **Planner statistics (`ANALYZE`)**: a random sample of each table that Postgres keeps, so it can estimate row counts and pick a plan; a fresh sample can change a close call between two plans.
- **Correlation (planner)**: how closely a column's order matches the rows' order on disk; high correlation makes index scans look cheap, so test data must not be loaded more tidily than real data arrives.
- **Bitmap scan / `BitmapAnd`**: reads one or more indexes into a bitmap of matching pages, combines them, then visits each page once; how Postgres uses two indexes for one query.
- **`COPY`**: Postgres's bulk load command, one stream of rows rather than one statement per row.
- **Zipf distribution**: a skew where the item at rank N is used about 1/N as often as the top one; a few Foods dominate, as in real logs.
- **pytest marker**: a label on tests that lets a run include or exclude them; `index_plans` keeps the full-seed checks out of the PR suite.
- **Mutation check**: breaking the thing on purpose to prove a test can fail; here, dropping indexes and watching the plan checks go red.
- **Topology spread constraint**: a scheduling rule that keeps a Deployment's pods balanced across failure domains; `maxSkew: 1` means the fullest and emptiest node may differ by at most one pod.
- **`pod-template-hash`**: a label Kubernetes adds to a Deployment's pods, with one value per revision of the pod template, so it tells a rollout's new pods from the old ones.
- **Synchronous replication**: the primary reports a commit as done only after a replica has it, so a failover cannot lose it; asynchronous replication reports first and copies after, which is faster but can lose the last commits.
- **Property-based testing**: state a rule that must hold for every input ("never a 5xx"), and let a tool generate the inputs, instead of writing examples by hand.
- **Hypothesis**: the Python property-based testing library under Schemathesis; it generates inputs and shrinks a failure to the smallest one that still fails.
- **Shrinking**: reducing a failing generated input to its simplest form, so the report shows `name: "0"` and not 200 random characters.
- **Fuzzing**: sending large amounts of generated, often malformed, input to find crashes nobody thought to test; a safety net, because it finds likely bugs and not every bug.
- **Contract testing**: checking that a running service really behaves as its published interface says, so clients can trust that interface.
- **Schemathesis**: a tool that turns an OpenAPI document into generated requests and checks each response against that document.
- **Lax vs strict validation**: lax mode converts near matches (`"5"` to `5`, `0` to `false`); strict mode refuses them, so the service accepts only what its contract says.
- **Form diffing**: comparing what a form holds with what was last saved, so Save sends writes only for what differs.
- **Partial failure**: some requests of a multi-request save succeed and others fail, leaving the data between the old state and the new one; there is no transaction across requests, so the client must show what is left and allow a retry.
- **`Intl.DateTimeFormat`**: the browser's built-in date formatter; given a time zone, it can report that zone's UTC offset at a moment, daylight saving included.
- **`touch-action`**: a CSS property listing which touch gestures the browser may handle itself; `pan-x pan-y` allows scrolling only, so pinch and double-tap zoom do nothing.
- **Form draft**: the state a form edits, shaped for typing (text fields, local row keys) rather than for the wire; a pure function turns it into the request body only when it is valid.
- **Strategy object**: a plain object of functions passed to shared code so one component serves several cases (`foodCatalog`, `exerciseCatalog`) without `if kind ===` branches inside it.
- **Remount by `key`**: changing a component's `key` makes React discard it and mount a fresh one, the simplest way to reset its internal state from outside.
- **Stretched link**: one real button whose `::after` box is stretched over a whole card, so the card is tappable anywhere while assistive tech still sees one named button.
- **Fast Refresh**: the dev server's hot reload for React; it only works on files that export components alone, which is why shared helpers live in their own modules.
- **Pseudo-element (`::after`)**: an extra box CSS draws on an element without any HTML for it; Tailwind's `after:` prefix styles it.
- **`appearance: none`**: turns off the browser's native drawing of a form control (iOS time pickers, select arrows), so the control follows the page's CSS like a plain box.
- **Infinite scroll**: a list that loads its next page when the user scrolls near its end, instead of numbered pages; here it is driven by keyset cursors, so rows never repeat or skip.
- **`IntersectionObserver`**: a browser API that calls back when an element enters or leaves the viewport; the cheap way to notice "the end of the list is on screen" without scroll listeners.
- **`useInfiniteQuery`**: TanStack Query's hook for paged data; it keeps every loaded page in one cache entry and fetches the next with `getNextPageParam` (here, the page's `next_cursor`).
- **Merging cursor streams**: reading two separately paged, same-ordered lists into one view; an item is safe to show only once every unfinished stream has read past its position.
- **Read-only view**: a screen that shows data without edit controls, so it can answer questions with no risk of changing anything; edits are a link away, on the screen built for them.
- **`useEffectEvent`**: a React hook for a function an effect calls but should not re-run for; it always sees the latest props, so the effect can depend on nothing.
- **Accessible name**: the text a screen reader announces for a control, computed from its content or `aria-label`; adjacent `<span>`s can run together ("Nov 62 sets") unless the name is set explicitly.
- **Taint-based eviction**: when a node stops reporting, Kubernetes taints it `unreachable:NoExecute`, and pods without a matching toleration are deleted so their controllers can replace them elsewhere.
- **`tolerationSeconds`**: how long a pod tolerates a `NoExecute` taint before eviction; Kubernetes adds 300s for `unreachable` to every pod, which is why a dead worker's pods move after about 5 minutes.
- **`pg_rewind`**: a Postgres tool that winds a former primary back to the point where it diverged from the new one, so it can rejoin as a replica without a full copy.
- **Minimum recovery point**: the WAL position a replica must replay to before its data is consistent; until then it refuses connections.
- **Checkpoint**: Postgres writing every changed page to disk and recording a WAL marker, so crash recovery can start from there.
- **Tailscale / tailnet**: a WireGuard-based private network that joins your devices wherever they are; your tailnet is the set of devices allowed in, so nothing outside it can even connect.
- **Admin console (Tailscale)**: Tailscale's hosted website (`login.tailscale.com/admin`) for managing a tailnet: devices, users, access rules, settings and API credentials.
- **Tailnet policy file**: one HuJSON document holding every access rule of a tailnet; once it exists, anything it does not allow is denied.
- **HuJSON**: JSON that also allows comments and trailing commas, so a config file can explain itself.
- **Policy as code**: keeping access rules in a reviewed, versioned file that a pipeline applies, instead of clicking them into a console; git becomes the history and the undo.
- **Tag (Tailscale)**: an identity for a machine (`tag:k8s`) in place of a person's; a tagged device belongs to no user and keeps working if the person who added it leaves.
- **`tagOwners`**: the policy section listing who may give a device each tag.
- **Grant (Tailscale)**: one allow rule: these sources (`src`) may reach these destinations (`dst`) on these ports (`ip`). There are no deny rules, only the absence of a grant.
- **Autogroup**: a built-in Tailscale group filled in by role, such as `autogroup:owner` or `autogroup:member` (every person on the tailnet), so a policy needs no email addresses.
- **`autoApprovers`**: the policy section that approves ahead of time what a device may announce, such as hosting a Tailscale Service, so no one has to click approve.
- **Device approval**: a tailnet setting that holds every new device in a waiting state until an admin approves it; signing in is not enough to get on the network.
- **OAuth client (Tailscale)**: a non-person credential for Tailscale's API, limited to chosen scopes (such as `policy_file`), unlike a personal API key that can do everything its owner can and dies after 90 days; created on the admin console's Trust credentials page.
- **Defense in depth**: several independent layers of protection, so one failing (a device admitted by mistake) does not expose everything (a Pending User still sees no data).
- **OIDC (OpenID Connect)**: a standard login protocol on top of OAuth 2.0; an identity provider signs a token saying who the person is, and the app trusts that signature instead of storing passwords.
- **OAuth client ID**: identifies an application registered with an identity provider (our `web` app), never a person.
- **OAuth client secret**: the registered app's password, sent only server to server to swap a sign-in code for tokens; unlike the client ID it must never reach a browser or git.
- **`sub` (subject)**: the OIDC claim holding a person's stable, unique ID at one identity provider; the key that links a sign-in to our User.
- **Identity provider (IdP)**: the service that signs people in and issues OIDC tokens (e.g. Authentik, Zitadel, Auth0).
- **Registrar**: the company you rent a domain name from; its job here is only to say which nameservers are authoritative for the domain.
- **Nameservers (DNS host)**: the servers that answer lookups for a domain; switching them at the registrar moves where you edit records.
- **A record**: a DNS row mapping a name to an IPv4 address.
- **DNS-01 challenge**: Let's Encrypt proves you control a domain by checking a TXT record you publish; it never connects to the server, so private IPs are fine.
- **DNS rebinding protection**: a router or resolver feature that drops public DNS answers pointing at private addresses, to stop websites from attacking your LAN.
- **Split DNS**: sending lookups for one domain to a chosen resolver; Tailscale pushes this to devices on the tailnet.
- **TailVIP / Tailscale Service**: a stable tailnet address that belongs to a service rather than a machine, so it survives the machines behind it being replaced.
- **ProxyGroup**: a set of Tailscale proxy pods run by the Tailscale Kubernetes Operator that carry tailnet traffic into the cluster.
- **Grey cloud (DNS only)**: a Cloudflare record that just answers DNS, without routing traffic through Cloudflare's proxy.
- **shellcheck**: a static analyser for shell scripts that flags quoting bugs, unset-variable traps and portability problems before the script runs.
- **Shebang (`#!`)**: a script's first line, naming the interpreter that runs it; the OS reads it, and our CI uses it to find shell scripts.
- **Base backup**: a full copy of a database's data files from one moment; useless alone for Postgres PITR, since WAL replayed on top is what brings it forward.
- **Generation (backup)**: one `pg` Cluster's lifetime, stored as its own `serverName` folder in the bucket; each restore starts a new one.
- **RPO (recovery point objective)**: how much recent data a disaster may cost, measured in time; ours is about a minute.
- **RTO (recovery time objective)**: how long until the service is back after a disaster; ours is the length of a restore.
- **PITR (point-in-time recovery)**: restoring a base backup, then replaying WAL only up to a chosen moment, e.g. just before a bad delete.
- **`pg_switch_wal()`**: closes the current WAL segment early so it can be archived now instead of when it fills or times out.
- **AWS SigV4**: the scheme S3-compatible APIs use to sign each request with a secret key; curl can do it with `--aws-sigv4`.
- **Restore drill**: actually restoring a backup on a schedule, because a backup nobody has restored has not been shown to work.
- **Passkey**: a login credential (a key pair) stored on your device and synced by iCloud Keychain; the site keeps only the public key, so there is no password to phish or leak.
- **Standalone mode**: an iPhone Home Screen web app running in its own window without Safari's interface, with cookies and storage separate from Safari.
- **Hard refresh (Argo CD)**: the `argocd.argoproj.io/refresh=hard` annotation, which makes Argo re-read git and re-render now instead of at its next 3-minute poll.
- **Bootstrap ordering**: building a system in the order its dependencies need (secrets, then database, then app, then auto-sync) so nothing starts against something that does not exist yet.
- **Authorization code flow**: the browser goes to the identity provider, the person signs in, the provider redirects back with a one-time code, and the app's server swaps that code plus its client secret for tokens.
- **ID token**: the signed JWT an OIDC provider returns, stating who signed in; its `sub` claim becomes the User's key.
- **Redirect URI**: the exact URL an identity provider may send the browser back to with the code; registered in advance so a code cannot be delivered elsewhere.
- **OAuth consent screen**: Google's settings for what people see when signing in and who may sign in (Testing: a hand-listed allowlist; In production: any Google account).
- **`HttpOnly` cookie**: a cookie the browser sends with each request but page JavaScript cannot read, so an injected script cannot steal the session.
- **oauth2-proxy**: an open-source reverse proxy that runs the OIDC sign-in, keeps the session in a cookie, and forwards only requests that have one.
- **Trusted header**: an identity header (e.g. `X-Forwarded-User`) set by a proxy and believed by the backend; safe only when nothing but the proxy can reach that backend.
- **Session store**: where a proxy keeps session state; either inside the encrypted cookie itself (stateless) or in a server-side database like Redis (revocable).
- **Kustomize component**: a reusable chunk of Kubernetes config that several Kustomize bases include and patch, so shared settings live in one place.
- **`__Host-` cookie prefix**: a cookie name prefix that makes the browser reject the cookie unless it is `Secure`, has `Path=/` and has no `Domain`, pinning it to one exact host.
- **`iss` (issuer)**: the OIDC claim naming who issued a token, e.g. `https://accounts.google.com`; a `sub` is unique only within one issuer, so Users are keyed by both.
- **Audit log (table)**: an append-only table recording who changed what and when, written in the same transaction as the change so the two cannot disagree.
- **`kubectl exec`**: runs a command inside a container that is already running in the cluster, like SSH into it; used here to run admin commands with the pod's own config and database account.
- **Management command**: an admin task shipped inside the app's own image and run against live config (Django's `manage.py`, `rails console`), so it shares the app's code and tests.
- **Refresh token**: a long-lived credential an identity provider can issue at sign-in so a server can get fresh short-lived tokens later without the person signing in again; Google issues one only when asked with `access_type=offline`.
- **Sliding vs fixed expiry**: sliding resets the expiry clock with each use (expires after N idle days); fixed counts from sign-in (expires N days later no matter what).
- **ITP (Intelligent Tracking Prevention)**: Safari's rules that delete or cap stored site data to limit tracking, e.g. a 7-day cap on storage that page JavaScript writes.
- **Cookie secret**: the key oauth2-proxy uses to encrypt and sign session cookies; whoever holds it can forge a session for any User.
- **Projected ServiceAccount token**: a short-lived JWT Kubernetes mounts into a pod, signed by the cluster, proving "I am ServiceAccount X in namespace Y" to whoever accepts that audience.
- **Workload identity**: a machine proving who it is with a credential its platform issues on the fly (like a projected ServiceAccount token) instead of a stored secret.
- **Envoy**: an open-source L7 proxy; Cilium runs it to serve Gateway API resources, matching `HTTPRoute`s and forwarding to pods.
- **EndpointSlice**: the list Kubernetes keeps of a Service's ready pod IPs; a pod failing readiness drops out of it.
- **TLS termination**: the point where encrypted traffic is decrypted; past it, a proxy can read paths and headers.
- **OAuth `state` parameter**: a random value the client stores in a cookie and sends to the IdP; the callback must return it unchanged, proving the sign-in was started here.
- **Per-tenant vs shared reference data**: per-tenant rows belong to one User and only they see them; shared reference data is one read-only copy every User reads, like a country list.
- **Copy-on-pick**: picking a shared item copies its values into the User's own row, so later edits on either side never affect the other.
- **Snapshot vs computed value**: a snapshot copies a value onto the row when it is written and never changes; a computed value is worked out from current data on every read, so corrections flow into history.
- **`numeric`**: Postgres's exact decimal type; unlike `float`, `0.1 + 0.2` is exactly `0.3`, so sums of nutrition values do not drift.
- **Multi-column CHECK**: a table-level CHECK that reads several columns of the row, for rules like "these five are all set or all null" that no single column can state.
- **`num_nonnulls(...)`**: a Postgres function that counts how many of its arguments are not null; `IN (0, 5)` on five columns means all or nothing.
- **CHECK and NULL**: a CHECK rejects a row only when it evaluates to false; null counts as a pass, so `kcal BETWEEN 0 AND 10000` allows a missing `kcal`.
- **`REVOKE`**: removes a privilege granted earlier; here it narrows the default privileges for one table, so `api_rw` can read `reference_foods` but not write it.
- **Fast default**: since Postgres 11, `ADD COLUMN ... DEFAULT <constant>` stores the default once in the catalog instead of rewriting every row, so it stays fast on a large table.
- **Additive API change**: adding an optional field, parameter or endpoint without changing what exists, so clients written for the old contract keep working with no new version.
- **All-or-nothing group as a nullable object**: fields that must be all set or all absent are modelled as one object that is either present or `null`, so the schema itself rules out a half-filled group.
- **Idempotent load**: a data load that can run any number of times and leaves the same rows as running it once, which makes it safe to run on every deploy.
- **Upsert**: one statement that inserts a row or, if its key already exists, updates it (`INSERT ... ON CONFLICT ... DO UPDATE` in Postgres).
- **`IS DISTINCT FROM`**: a comparison that treats null as an ordinary value, so `null IS DISTINCT FROM null` is false where `null <> null` is unknown; used to skip an update that would change nothing.
- **`xmin`**: a hidden Postgres column holding the id of the transaction that last wrote the row; unchanged across a load proves the row was not rewritten.
- **`GROUP BY`**: collapses rows that share a value (here a Day) into one row, with aggregates such as `sum()` computed over each group.
- **`FILTER (WHERE ...)`**: restricts one aggregate to some of a group's rows, e.g. counting only the Entries that could not be counted, without a second query.
- **Query plan (`EXPLAIN`)**: Postgres's chosen steps for running a query (which indexes, which joins); `EXPLAIN ANALYZE` also runs it and reports real row counts and times.
- **Hash join**: joining two tables by building an in-memory lookup table from one and probing it with each row of the other; fast when one side is read whole anyway.
- **Code splitting / lazy route**: shipping part of a web app as a separate file fetched only when its screen is first opened, so rarely used code does not slow the first load.
- **Keyset walking by range**: reading a long history in pages by asking for "the rows before the oldest one I have", instead of an offset that shifts when rows are added.
- **Zero baseline**: whether a chart's y axis starts at 0; right for amounts compared by size, wrong for measures read by their change, which it flattens.
- **Secondary encoding**: showing a category by shape or label as well as color, so a chart still reads for colorblind readers and in grayscale.
- **Network layers (TCP/IP model)**: networking split into stacked jobs: link (one hop on a wire or Wi-Fi), IP (addressing and routing across the internet), transport (TCP/UDP, ports and reliable delivery), application (HTTP, DNS); TLS sits between transport and application.
- **IP address**: the number that identifies a machine on a network; public ones are reachable from the internet, private ones (`192.168.x.x`, `10.x.x.x`) only inside their own network.
- **Packet**: one small chunk of data with a source and destination IP on the front; a request is split into many packets that routers forward hop by hop.
- **Port**: a number (0-65535) that picks which program on a machine gets the traffic; HTTPS is 443 and HTTP is 80 by convention.
- **TCP**: a transport protocol that turns unreliable packets into an ordered, reliable byte stream between two ports (a "connection"); UDP is the no-guarantees alternative.
- **HTTP**: the application protocol of the web: a request (method, path, headers, body) and a response (status, headers, body), sent as plain text unless wrapped in TLS.
- **TLS**: encryption wrapped around a TCP connection, so only the two ends can read it; the server proves its identity with a certificate. HTTPS is HTTP inside TLS.
- **Certificate**: a file that says "this public key belongs to `app.nibblejiggle.xyz`", signed by a certificate authority (e.g. Let's Encrypt) that browsers trust.
- **DNS**: the internet's phone book: turns a name like `app.nibblejiggle.xyz` into an IP address (A record) or into another name to look up (CNAME record).
- **NAT / port-forwarding**: a home router shares one public IP across all home devices and drops unsolicited inbound traffic; port-forwarding is the router setting that sends inbound traffic on a port to one device.
- **Reverse proxy**: a server that receives requests on behalf of other servers and forwards them; Cloudflare's edge, the Cilium Gateway and oauth2-proxy are all reverse proxies.
- **Outbound tunnel**: a program inside a private network dials out to a provider and holds the connection open, so the provider can send requests back down it without any inbound port opened.
- **Edge / CDN**: a provider's data centers spread worldwide; your visitors connect to the nearest one instead of to your server. Cloudflare's edge is where its features run.
- **Proxied record (orange cloud)**: a Cloudflare DNS record that answers with Cloudflare's own IPs, so traffic goes through Cloudflare's edge first.
- **WAF (Web Application Firewall)**: rules at a reverse proxy that inspect decrypted HTTP requests and block bad ones (known attack patterns, too many requests, bots).
- **DDoS**: distributed denial of service: flooding a target with traffic from many machines so real users cannot get through.
- **Certificate authority (CA)**: an organization whose signing key is pre-installed in browsers and phones; a certificate it signs is trusted everywhere. Let's Encrypt is a free one.
- **ACME**: the protocol Let's Encrypt speaks: request a certificate, prove you control the name with a challenge, receive the signed certificate (valid 90 days).
- **HTTP-01 challenge**: Let's Encrypt proves control of a name by fetching a token from `http://<name>/.well-known/acme-challenge/`; needs the server reachable from the internet on port 80.
- **SNI (Server Name Indication)**: the hostname a client sends unencrypted at the very start of a TLS handshake, so a server holding several certificates knows which one to present.
- **Apex domain**: the bare registered name (`nibblejiggle.xyz`) with no subdomain in front.
- **CNAME flattening**: Cloudflare answering a CNAME at the apex with the target's IPs, because plain DNS forbids a CNAME next to the apex's other records.
- **Universal SSL**: the free certificate Cloudflare issues and renews for a proxied zone, covering the apex and one level of subdomain; it is what browsers see on link A.
- **ClusterIP vs LoadBalancer Service**: a ClusterIP Service has a virtual IP reachable only from inside the cluster; a LoadBalancer Service also gets an address outside it (here, once, a home LAN IP).
- **Network policy**: firewall rules between workloads ("only pods labelled X may connect to Y on port Z"), enforced by the CNI; with none, every pod can reach every other pod.
- **Cilium identity**: a number Cilium gives each group of pods with the same labels; policies match identities instead of IPs, and Gateway traffic carries the special `reserved:ingress` identity.
- **Fail closed**: when a check is missing or broken, the result is "denied" rather than "allowed"; a route-walk test that covers new routes by default fails closed, a per-route checklist fails open.
- **Egress policy**: a network policy on outgoing traffic ("pod X may only connect to Y"); it limits what a compromised or misconfigured workload can reach, the mirror of an ingress policy.
- **Kill switch (runtime flag)**: a setting that turns a feature off while the system runs, with no deploy; kept in the database here so GitOps self-heal cannot revert it.
- **Social engineering**: getting access by fooling a person rather than breaking a system, e.g. a Google account named like an invitee waiting to be approved by mistake.
- **Out-of-band verification**: confirming a claim through a separate channel (a text, a call) the attacker does not control.
- **Rate limit**: a cap on how many requests one client (an IP, a User) may make in a time window; past it, requests are refused until the window moves on.
- **Fixed window vs moving window**: a fixed window resets its count on the clock (every minute), so up to twice the limit can pass across a reset; a moving window counts the last N seconds at every request.
- **429 Too Many Requests**: the HTTP status for "you hit a rate limit"; it is the client's answer, not a server fault.
- **`Retry-After`**: a response header telling the client how many seconds to wait before trying again.
- **Bot Fight Mode**: a Cloudflare Free setting that challenges traffic it thinks is automated; it covers the whole domain and cannot be skipped per path.
- **ExternalAuth filter**: the Gateway API's way to put an `ext_authz` check on an `HTTPRoute`, so the Gateway asks an auth service before forwarding each request.
- **Gateway API release channels**: Gateway API ships two CRD bundles; standard holds stable, backward-compatible fields, experimental adds fields that may change or be removed between releases.
- **Exposure window**: the time between a fix for a known vulnerability being published and that fix running in your system; attackers target exactly this gap.
- **Certificate Transparency (CT) logs**: public, append-only logs of every TLS certificate issued; anyone can read them, so a new hostname becomes visible to scanners as soon as it gets a certificate.
- **Dependabot alerts / security updates / version updates**: GitHub's built-in dependency tooling; alerts email you when a lockfile entry has a known advisory, security updates open a PR for the fixed version, version updates open PRs for every new release on a schedule.
- **Renovate**: a third-party bot that does what Dependabot version updates do but can also read custom files through regex rules; it needs write access to the repo.
- **Release-watch**: subscribing to a GitHub repo's releases and security advisories (Watch -> Custom) so each new version arrives as an email.
- **GitHub Environment**: a named deploy target in a repo with its own secrets and rules, e.g. "only the `main` branch may use it"; workflow jobs must name it to read its secrets.
- **Deployment branch policy**: an Environment's list of branches allowed to use it; a job on any other ref fails before its first step and never sees the Environment's secrets.
- **Remotely vs locally managed tunnel**: a Cloudflare Tunnel's routes are held either by Cloudflare (set by dashboard, API or Terraform; `cloudflared` needs only a token) or in a `config.yml` next to `cloudflared` (plus a credentials file).
- **Terraform provider**: the plugin that teaches Terraform one API, e.g. `cloudflare/cloudflare`; pinned in `.terraform.lock.hcl`.
- **Terraform state**: Terraform's record of which real objects it manages and their last known settings; it can hold secrets, so where it lives matters.
- **Remote backend**: storing Terraform state in a shared service (S3-style bucket, HCP Terraform) with locking, so several people or CI can apply safely.
- **Drift**: the real system no longer matching the code, usually from a manual change; `terraform plan` reveals it.
- **`terraform import`**: adopting an object that already exists into state, so Terraform manages it without recreating it.
- **`toFQDNs`**: a Cilium egress rule naming DNS names instead of IPs; Cilium watches the pod's DNS answers and allows the IPs they return.
- **PodDisruptionBudget (PDB)**: a limit on how many of an app's pods voluntary disruptions (a node drain) may take down at once.
- **TTL (DNS)**: how many seconds a resolver may cache an answer before asking again; it bounds how long a DNS change takes to be seen everywhere.
- **Recursive resolver**: the server your device asks (home router, `1.1.1.1`); it walks root, then TLD registry, then the domain's nameservers, and caches each answer.
- **DNSSEC**: signatures on DNS answers so a resolver can detect forged ones; the parent zone vouches for the child's key with a DS record.
- **DS record**: a hash of a zone's signing key, held by the parent (the `.xyz` registry, set through the registrar); it must match the key the nameservers sign with, or the name stops resolving.
- **Hidden prompt (`read -rs`)**: reading a value from the keyboard without echoing it or putting it on a command line, so it stays out of the screen, shell history and `ps`.
- **ClusterIssuer**: a cert-manager object naming a certificate authority and how to prove control to it; cluster-wide, and it reads its Secrets only from cert-manager's own namespace.
- **ACME account**: a key pair cert-manager registers with Let's Encrypt and signs every order with; it is not tied to any certificate, so a rebuild can register a new one freely.
- **Let's Encrypt staging**: a test copy of Let's Encrypt with much higher rate limits whose certificates no browser trusts; used to prove the setup before asking production.
- **gateway-shim**: the cert-manager controller that reads the `cert-manager.io/cluster-issuer` annotation on a Gateway and creates a `Certificate` for each HTTPS listener's hostname.
- **Optimistic locking (Kubernetes)**: every object carries a `resourceVersion`; an update based on a stale version is refused, and the controller re-reads and retries instead of overwriting someone else's change.
- **Certificate -> CertificateRequest -> Order -> Challenge**: cert-manager's chain for one issuance: what you want, one attempt to get it, the ACME order for it, and one proof per name (here a DNS-01 TXT record); read them in that order when issuance stalls.
- **STRIDE**: a threat checklist (Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege) used to check a threat model has no blind spot.
- **Repudiation**: being unable to prove who did an action after the fact; countered by logs that tie each request to an identity.
- **Path-owning account**: an outside account (DNS, registrar, identity provider, code host) whose takeover hands over the app without touching the servers.
- **Loki**: Grafana's log store; it indexes only labels (pod, namespace) rather than full text, which keeps it cheap to run.
- **Drift (Terraform)**: the real object no longer matches the `.tf` files, usually after a dashboard click; `terraform plan` lists it as a change to undo.
- **Data source (Terraform)**: a read-only lookup (`data "..."`) of something Terraform does not manage, such as the Cloudflare zone; refreshed on every plan.
- **`import` block**: the config form of `terraform import`; its ID can be computed (here from data sources), and `plan` previews every adoption before `apply` writes any.
- **Partial backend config**: leaving a `backend` block empty and passing its settings at `terraform init -backend-config=...`, because backend blocks cannot read variables or expand `~`.
- **`prevent_destroy`**: a lifecycle flag that makes Terraform refuse any plan that would delete or replace the resource.
- **Ruleset and phase (Cloudflare)**: a phase is a point in request handling (custom rules, rate limiting); each zone has one entry ruleset per phase, holding its rules in order.
- **`umask`**: bits removed from a new file's permissions; `077` makes every file the process creates readable by its owner only.
- **Cilium entity**: a built-in name for traffic that is not an ordinary pod (`host` for the node itself, `ingress` for Cilium's Gateway Envoy, `world` for outside the cluster), usable in a policy where a pod selector would match nothing.
- **Cilium DNS proxy**: a resolver Cilium slips between a pod and kube-dns when a policy has a `dns` rule; it reads each answer so `toFQDNs` knows which IPs a name stands for.
- **`maxSurge` / `maxUnavailable`**: how far a rolling update may go above or below the replica count while it swaps pods; `0` / `1` means "remove one, then add its replacement".
- **`TUNNEL_TOKEN`**: the env var `cloudflared tunnel run` reads its token from, so the token stays off the command line that `ps` shows.
- **PKCE (Proof Key for Code Exchange)**: the client makes a random secret per sign-in, sends only its hash to the provider, and must show the secret when trading the code for tokens, so a stolen authorization code is useless on its own.
- **`SameSite` cookie attribute**: tells the browser when to send a cookie on requests started by another site; `Lax` sends it on top-level link clicks (so the return from Google works) but not on cross-site `POST`, `PUT` or `DELETE`, which blocks most CSRF.
- **OIDC discovery**: the provider publishes its endpoints and signing keys at `<issuer>/.well-known/openid-configuration`, so a client needs only the issuer URL; oauth2-proxy reads it once at start.
- **oauth2-proxy alpha config**: oauth2-proxy's YAML config file for upstreams, injected headers and providers; "alpha" means its shape can change between minor releases (it did in v7.14), so read release notes on every bump.
- **Docker host networking (`--network host`)**: the container shares the host's network stack, so a server bound to the container's `127.0.0.1` is reachable on the host's `127.0.0.1`; a published port (`-p`) can only reach the container's own interface.
- **`401` vs `403`**: `401 Unauthorized` means "I don't know who you are" (no identity: sign in); `403 Forbidden` means "I know who you are, and you may not do this" (a Pending User).
- **`ON CONFLICT DO NOTHING`**: an `INSERT` that silently skips a row whose unique key already exists, so two racing first requests cannot both insert or make one fail; unlike an upsert, the existing row is left untouched.
- **`IS DISTINCT FROM`**: SQL's null-safe "not equal"; `NULL <> 'x'` is `NULL` (neither true nor false), while `NULL IS DISTINCT FROM 'x'` is true.
- **Header encoding (Latin-1)**: HTTP header bytes have no declared encoding; Python servers decode them as Latin-1, so UTF-8 text a proxy puts in a header must be re-read as UTF-8 or "Nguyễn" arrives garbled.
- **Router dependency vs endpoint dependency (FastAPI)**: a function FastAPI runs before the endpoint; declared on one endpoint it guards that endpoint, and FastAPI runs each dependency once per request even if several ask for it.
- **Attack surface**: every way something outside can reach a system; removing a path shrinks it for good, while a firewall rule in front of a path only guards it for as long as the rule stays right.
- **GatewayClass**: the Gateway API object that names which controller runs a Gateway (here Cilium) and, through `parametersRef`, which settings it applies to every Gateway of that class.
- **`CiliumGatewayClassConfig`**: Cilium's settings object for a GatewayClass; here it shapes the Service Cilium generates for each Gateway.
- **`loadBalancerClass`**: a Service field naming which load balancer implementation may give it an outside IP; one that no implementation claims leaves the Service without one.
- **`CiliumClusterwideNetworkPolicy`**: a `CiliumNetworkPolicy` without a namespace; needed when the endpoint selected is not a pod, such as Envoy's `reserved:ingress` identity.
- **Gateway `Programmed` condition**: the Gateway API status saying the data plane is set up and the Gateway has an address; with no outside address on purpose, it stays `False` while Envoy still serves.
- **Auth gate (SPA)**: a check at the top of the app that decides what the person may see (here the Role from `GET /api/me`) before any screen renders and fires its own requests.
- **Module mock (`vi.mock`)**: Vitest swaps a whole module for a fake in one test file, so code that would do something tests cannot (here, reload the page) is recorded instead.
- **ASGI middleware**: a wrapper around the whole Python web app that sees every request on the way in and every response on the way out; "pure" ASGI means it works on the raw `scope`/`send` messages rather than Starlette's `BaseHTTPMiddleware`.
- **Path template**: the route as declared (`/api/v1/meals/{meal_id}`) rather than as requested (`/api/v1/meals/0197...`); logging it keeps ids and other values out of logs and groups requests per route.
- **Singleton row**: a table that can hold exactly one row, enforced by a key column whose only legal value is fixed (`id boolean PRIMARY KEY CHECK (id)`); used for one global setting such as the Sign-up brake.
- **Per-pod counter (the 2N ceiling)**: a rate limit counted in each replica's own memory; a load balancer spreads one User's requests across N pods, so they can make up to N times the limit before every pod refuses them.
- **`limits` (Python library)**: rate limiting algorithms (fixed and moving window) and counter storage (memory, Redis, ...), with no web framework attached; slowapi and Flask-Limiter are built on it.
- **Existence leak**: a response that differs between "not yours" and "not there" (say `403` vs `404`), so an attacker can probe which ids are real; giving both the same answer closes it.
- **Router-level dependency**: a FastAPI `Depends` attached when a router is included, so it runs before every endpoint in that router without each endpoint asking for it.
- **Layout route**: a route with no page of its own that draws a shared frame (a header, a tab bar) and renders whichever child route matched inside it, through React Router's `<Outlet />`.
- **Catch-all route**: a route with `path="*"` that matches any URL no other route claims; it renders the Not Found page.
- **Redirect route**: a route whose only job is to send an old URL to its new one (`<Navigate replace />`), so links saved before a move keep working.
- **Synthetic monitoring**: a script that acts like a visitor on a schedule and checks the answers, so a broken or wrongly exposed site is caught before a real visitor finds it; here the daily `public-probe` workflow.
- **Testing the commit vs testing the deployment**: CI tests prove the code in a commit is right; a probe of the live site proves what is actually running, with its config, edge settings and infra, is right, and can fail when no commit changed.
- **GitHub Actions `schedule` trigger**: runs a workflow on a cron line in UTC from the default branch only; GitHub may start it minutes late at busy times, and turns it off after 60 days without repo activity in a public repo.
- **Expression injection (GitHub Actions)**: `${{ }}` is pasted into a `run:` script as text before the shell reads it, so user-controlled input there can run commands; passing it through `env:` keeps it a plain variable.
- **App session vs provider session**: two separate sign-ins in two cookies; signing out of the app (`/oauth2/sign_out`) deletes the app's cookie only, while the identity provider's own cookie (Google's) keeps the browser signed in to Google.
- **RP-initiated logout**: an OIDC feature where the app (the relying party) sends the browser to the provider's `end_session_endpoint` to end the provider's session too; Google does not offer it.
- **Client-side filtering**: the browser downloads a whole small list once and filters it in memory as the user types, with no request per keystroke; it trades a bigger first response and simpler matching for instant results.
- **Bounded response**: an API answer whose size has a fixed ceiling (a maximum `limit`), so no caller, honest or not, can make the server build and send an arbitrarily large reply.
- **Account takeover**: getting into a system by logging in as its owner (phished or reused password, hijacked recovery) instead of breaking its defenses; usually the cheapest attack on a well-built system.
- **TOTP (authenticator app)**: a 6-digit code computed from a shared secret and the current time, valid ~30 seconds; tied to your device, but a fake login page can relay it live.
- **SIM swap**: an attacker convinces a phone carrier to move your number to their SIM, then receives your SMS codes; why SMS is never a second factor or recovery method here.
- **Required but nullable (OpenAPI)**: the key is always present in the JSON (`required`) but its value may be `null`; clients never have to handle a missing key, only an empty value. Pydantic produces this for `str | None` with no default.
- **Safe-area inset (`env(safe-area-inset-bottom)`)**: a CSS value the phone fills with the height of hardware or system UI over the page edge, such as the iPhone home indicator; it stays 0 unless the viewport meta tag sets `viewport-fit=cover`.
- **`aria-current="page"`**: marks the link to the screen you are on, so a screen reader says "current page" and tests can find the active tab without reading colours.
- **Adjusting state while rendering**: React's pattern for state that must follow a changing input (here the URL): compare and call `setState` during render behind a guard, instead of in an effect that would commit a stale frame first.
- **Code point vs UTF-16 code unit**: JavaScript strings index by 16-bit units, so `"𝒜"[0]` is half a character; `Array.from(s)` splits by code point (whole characters), which is what "first letter" needs.
- **`position: fixed` vs `position: sticky`**: a fixed element is pinned to the screen and takes no space in the page, so content can end up under it; a sticky element keeps its place in the page and only pins while its parent is on screen, so the page's end always scrolls clear of it.
- **`z-index`**: which of two overlapping positioned elements is drawn on top; higher wins (the bar's 40 sits under a sheet's 50).
- **`dvh` (dynamic viewport height)**: 1% of the screen height as it is right now, which changes as a phone's browser toolbar shows and hides; `100dvh` means "exactly one screen tall".
- **`pointer-events: none`**: makes an element let taps and clicks pass through to whatever is under it, while still being drawn.
- **CSS custom property (`--name`)**: a variable defined in CSS and read with `var(--name)`; one value that several rules share, so they cannot drift apart.
- **Query key prefix matching (TanStack Query)**: `invalidateQueries({ queryKey: ["day-totals"] })` hits every cached query whose key starts with that array, so one call refreshes the Meals window's one-Day total, Search's ranges and Dashboards' windows together.
- **Mutation testing**: deliberately breaking the code a test claims to cover (here, deleting an invalidation) and checking that the test fails; a test that still passes was not testing that line.
- **Escaping `LIKE` wildcards**: in SQL `LIKE`, `%` means "any text" and `_` means "any one character", so user text is escaped (`\%`, `\_`, `\\`) before it goes inside a pattern; otherwise typing `%` would match every row.
- **Natural key**: a key that comes from the data itself, like a date, rather than one made up for the row like a UUID; a Day is one, so it alone can order and page a list of Days.
- **Two-step page read**: first pick the page's keys (here, Days), then load everything under those keys in a second query; the page boundary falls between keys, so nothing under one key is ever split.
- **Hashed SubPlan**: Postgres runs an `IN (SELECT ...)` subquery once, keeps its rows in a hash table, then checks each outer row against it in constant time.
- **BitmapAnd**: Postgres reads two indexes separately, marks matching rows in two bitmaps, and keeps only rows in both; here "this User's Foods" AND "names containing the text".
- **Series (charts)**: one sequence of values a chart draws as a unit, such as one line; Recharts draws one per `<Line>`, and each `<Line>` connects only its own points.
- **Per-point encoding**: showing a category by changing how one point of a series is drawn (its color or shape), instead of splitting that category into its own series; the line stays continuous through it.
- **`initialDimension` (Recharts)**: the size a `ResponsiveContainer` draws at before it has measured its box; it also lets the chart render in jsdom, which never measures anything.
- **Embedded reference vs full resource**: an API returns a lean pointer (`CatalogRef`: id, name, archived) where an item sits inside something else, such as a Food inside a Meal, and the fuller shape (`CatalogItem`, plus `last_used_day`) only from the item's own endpoints; each response carries what its readers need.
- **Lazy loading on interaction**: code splitting keyed to a user action rather than a route: the chunk is fetched the first time a control (here, opening the Dashboard section) needs it, so visiting the screen alone never pays for it.
- **`React.lazy` + `Suspense`**: `lazy(loader)` wraps a function returning `import()`; React calls it on the component's first render and shows the nearest `<Suspense fallback>` until the chunk arrives. The loader runs once per page load.
- **Implied URL default**: a query parameter whose default depends on other parameters (`/history?id=x` with no `tab` means Exercise), so links written before a default changed still open what they used to; the writer must then spell out the parameter whenever it differs from what the reader would infer.
- **Mutation check**: deliberately breaking the code a test guards (here, rendering the chunk while closed) to confirm the test fails; a test that still passes was not testing what it claims.
- **Live region (`role="status"`)**: an element a screen reader watches and reads aloud when its text changes, without moving focus; `status` is polite, so it waits for a pause. It must already be in the page before the text changes, or the change is often missed.
- **`rootMargin` (`IntersectionObserver`)**: grows the area the observer counts as "in view", so `0px 0px 400px 0px` fires while the target is still 400 px below the screen; used to start loading the next page before the user reaches the end.
- **Required URL parameter as an empty state**: when a view means nothing without a choice (an Exercise for History's Exercise side), the screen reads "no `id` in the URL" as its own state, renders only the ways to choose, and never asks the API for data it cannot use yet; clearing the choice is just removing the parameter.
- **Look-ahead paging (limit + 1)**: ask for one row more than a page and hide the extra one; if it came back, another page exists and starts at it, so the end of a list never costs an empty request. Used where an endpoint pages by a bound (`to`) rather than a cursor.
- **One endpoint, two views**: the same read serving different screens with different access patterns, each with its own cache entry: History's Exercise Dashboard reads a whole range of Sessions at once to chart it, while Recent Days reads the same endpoint a page at a time.
- **Render prop**: a component that takes a function returning JSX (`renderDay`) so the caller decides what each item looks like while the component owns the shared behavior around it (paging, status, retry).
- **`ButtonContext` (React Aria)**: how a React Aria parent (ComboBox) passes props to every `Button` inside it, which makes each one the menu trigger; `<ButtonContext.Provider value={null}>` opts a nested button out, as the × Clear button does.
- **Fake timers**: replacing `setTimeout` and the clock with ones a test moves by hand (`vi.advanceTimersByTime`), so a time-based rule such as a debounce is checked exactly, whatever the machine's speed.
- **Escaping regex characters**: in a regular expression, `.` `+` `(` and similar have meanings, so user text is escaped (`\.`, `\+`) before it goes inside a pattern; otherwise a filter of `c++` would be an invalid or different pattern. The browser-side twin of escaping `LIKE` wildcards.
- **Highlighting without `innerHTML`**: splitting text into pieces and wrapping the matches in `<mark>` elements as React nodes, so user text is always rendered as text and can never become markup or script (no XSS).
- **`SearchField` (React Aria)**: a text field with `type="search"` whose inner `Button` is wired as a clear button and whose Escape key empties it, calling `onClear`.
- **Translating redirect**: a redirect route that rewrites the old URL's query into the new screen's params instead of passing it through, used when the new screen reads the same param names differently (`/history/search?what=food&id=…` becomes `/history?q=<name>`).
- **Canonical URL**: the one URL a screen writes for a given view, so a redirect, a reload and a tap all land on identical addresses; built here by reusing the screen's own writer (`toHistoryParams`).
- **Log vs manage split**: the frequent job (logging a Meal) stays fast and never stops for upkeep; the rare job (fixing a Food's label, archiving, deleting) gets its own screens, here Profile's Catalog pages.
- **Placeholder data (`keepPreviousData`)**: TanStack Query keeps showing the last answer while a query with a new key loads, so flipping a filter swaps the rows in place instead of flashing "Loading...".
- **`setQueryData`**: writes a mutation's answer straight into the cache under a query key, so an open screen shows the saved value at once without asking the server again.
- **Mutation reset (`mutation.reset()`)**: clears a finished mutation's error and data; done here when the name changes, so a clash about the old name stops showing.
- **Client-made id**: the browser picks the new item's id (a UUIDv7) before the first request, so a retried or "Save anyway" PUT writes the same item instead of a second one.
- **`min-h-0` in a flex column**: a flex child normally refuses to shrink below its content; `min-h-0` lifts that, so a capped parent can squeeze it and an inner `overflow-y-auto` part scrolls instead.
- **`overscroll-contain`**: when a scrolling list hits its end, the swipe stops there instead of scrolling the page or sheet behind it.
